# 点阵屏 UI 框架 —— 移植接口清单

本目录（`apps/common/ui/ui_framework/`）是 JL703N/BR27 上 SSD1306 128x64 单色点阵屏的
完整 UI 框架。移植到别的平台时，需要由**宿主环境提供**下面这些接口。

> 数据来源：对**参与编译的 39 个 `.c`** 的目标文件做符号分析（不含 `ui_cpu/`，它不参与编译，
> 原因见本目录 `Makefile` 末尾）。
> **内部定义 428 个符号，对外依赖 69 个。** 复跑方法见文末第 7 节。

---

## 1. OS / 任务调度（14 个，必须）

UI 是独立任务，靠消息队列驱动。这一组不实现，框架跑不起来。

| 接口 | 用途 |
| ---- | ---- |
| `task_create` | 创建 UI 任务 |
| `os_taskq_pend` / `os_taskq_post_type` | UI 消息队列的收 / 发 |
| `os_sem_create` / `os_sem_pend` / `os_sem_post` | 同步（`ui_show_main` 要等 UI 画完才返回） |
| `os_time_dly` | 延时 |
| `os_current_task` | 判断当前是否在 UI 任务上下文 |
| `spin_lock` / `spin_unlock` | 临界区 |
| `local_irq_disable` / `local_irq_enable` | 关中断临界区 |
| `__cpu_irq_disabled` / `CONFIG_CPU_UNMASK_IRQ_ENABLE` | 中断状态查询 / 配置 |

引用方：全部集中在 `platform/lcd_ui_api.c`。

## 2. 内存（3 个，必须）

| 接口 | 用途 |
| ---- | ---- |
| `malloc` / `free` | 控件树节点、显存、字模缓冲 |
| `zalloc` | 清零分配（资源路径拼接、控件初始化） |

引用方：`res/mem_var.c`、`ui_dot/ui_core_api.c`、`ui_dot/ui_core_dot.c`、`font/*` 等 9 个文件。

> 框架**启动后仍会动态分配**（资源缓存、字模），不是纯静态设计。移植到无堆环境需要改造。

## 3. libc（8 个，必须）

`printf` `puts` `sprintf` `strcmp` `strcpy` `strlen` `strncmp` `memcmp`

> `printf` / `puts` 只用于日志与断言；若目标平台无输出，可做成空实现。
> 注意 `puts` 与 `printf` 在本框架里**两种形态都存在**（部分是源码直接调 `puts`，
> 部分是 `printf("...\n")` 被编译器折叠成 `puts`），实现时两个都要有。

## 4. 定时器 / 看门狗（5 个，必须）

| 接口 | 用途 | 引用方 |
| ---- | ---- | ------ |
| `sys_timer_add` / `sys_timer_del` | 页面定时刷新（时间、电量、进度） | `lcd_ui_api` `ui_platform` |
| `wdt_clear` / `wdt_clr` | 整屏推送等长操作中喂狗 | `ui_pushScreen_manager` `lcd_ui_api` |
| `delay_2ms` | 屏复位时序 | `oled_spi_ssd1306_128x64` |

> `wdt_clear` 与 `wdt_clr` 是**两个不同的名字**，原 SDK 里各有出处，移植时都要提供
> （或其中一个做别名）。

## 5. 硬件适配层（8 个，换平台必改）

**这是移植工作量的大头。** 全部只被 `platform/ui_pushScreen_manager.c` 一个文件调用 ——
换平台时基本只需重写这一个文件的推屏通道。

| 接口 | 用途 |
| ---- | ---- |
| `spi_open` | 打开 SPI 控制器 |
| `spi_send_byte` | 单字节发送（发面板命令） |
| `spi_dma_send` | **DMA 批量推送显存**（主推屏通道） |
| `spi_dma_set_addr_for_isr` | 设置 DMA 完成中断的缓冲地址 |
| `spi_get_pending` / `spi_clear_pending` | 中断标志查询 / 清除 |
| `get_hw_spi_config` | 取板级 SPI 配置 |
| `gpio_set_mode` | 引脚复用配置（23 处） |

另有屏侧的 `JL_PORTC`（背光 / 复位脚）直写，在 `lcd_drive/oled_spi_ssd1306_128x64.c` 里，
换屏时连同面板命令序列一起改。

> **本框架不使用 IMD 硬件推屏**。BR27 的 IMD 驱动（`ui_cpu/`）在本工程是死代码，
> 实测最终固件 0 处 IMD 寄存器访问。详见本目录 `Makefile` 末尾与
> `cpu/br27/tools/ui_reimpl/README.md` §3.3。

## 6. 存储 / 资源访问

### 6.1 资源文件 VFS（8 个，必须）

读 `.sty` / `.res` / `.str` 与字库文件。`res/resfile.c` 只是这一组的薄封装。

`resfile_open` `resfile_read` `resfile_seek` `resfile_close`
`resfile_get_len` `resfile_get_attrs` `mount` `fclose`

引用方：`res/resfile.c`、`font/font_sdfs.c`、`ui_dot/lyrics.c`、`platform/ui_resources_manager.c`

### 6.2 Flash 直存（4 个，仅歌词功能需要）

| 接口 | 用途 |
| ---- | ---- |
| `sfc_erase` / `sfc_write` | 把解析后的歌词索引写回 flash |
| `sdfile_cpu_addr2flash_addr` / `sdfile_flash_addr2cpu_addr` | CPU 地址 ↔ flash 物理地址换算 |

引用方：只有 `ui_dot/lyrics.c`。**不要歌词功能可以不实现。**

## 7. 平台约定（不是函数，但必须提供）

| 接口 | 类型 | 说明 |
| ---- | ---- | ---- |
| `control_ops_begin` / `control_ops_end` | **链接脚本段符号** | 控件类型注册表的收集边界。**漏了控件就注册不上**，表现为界面元素整块不显示 |
| `ui_style_begin` / `ui_style_end` | 同上 | UI 风格注册表 |
| `lcd_interface_begin` / `lcd_interface_end` | 同上 | 屏驱注册表（`REGISTER_LCD_DEVICE()` 落点） |
| `cpu_assert` / `config_asser` | 断言 | `ASSERT()` 宏的落点；`config_asser` 为假时只打印不停机 |
| `log_print` / `log_tag_const_d_UI` | 分级日志 | 可做空实现 |
| `CRC16` | 校验 | 资源头 / 数据校验、资源缓存指纹 |
| `ASCII_IntToStr` / `ASCII_ToUpper` | 字符串工具 | 数字控件格式化、资源名比较 |
| `JLUI_TYPE_AND_VERSION` | 全局 `int` 变量 | 资源文件魔数校验的开关位 |

> 三对段符号是移植时**最容易漏**的一项：它们不是函数，链接脚本里必须保留对应的
> `.control_ops` / `.ui_style` / `.lcd_if_info` 段收集规则。
> 自查方法：链接后 `grep -c "^control_ops_" <lst 文件>`，本工程正常值是 8。

## 8. ⚠️ 原厂就缺定义的（现在靠 LTO 丢掉才链接得过）

这些符号**全工程都没有定义**，之所以链接得过，是因为引用它们的代码路径在本配置下
是死代码，被 LTO 整个丢掉了。**一旦对应功能变活，链接会直接失败。**

> 原先是 5 个。`get_mixed_pixel` 已在加固时就地补上一份 `static` 实现
> （见 `cpu/br27/tools/ui_reimpl/README.md` §9.8），**现在剩 4 个**。

| 接口 | 引用方 | 情况 |
| ---- | ---- | ---- |
| `GetThaiLanguageCharacterData`<br>`IsThaiOneWord_W`<br>`ThaiLanguagecompose` | `font/font_other_language.c` | 泰语支持。靠 `lange_info_table` 恒为 NULL 被 LTO 消除 |
| `norflash_hardware_read_watch` | `res/resfile.c` | 其封装 `_norflash_read_watch` 零调用者 |

## 9. 移植工作量参考

按"要动脑的程度"排序：

1. **SPI + GPIO（8 个）** —— 重写 `platform/ui_pushScreen_manager.c` 的推屏通道。
   这是唯一需要真正理解时序的部分。
2. **资源文件 VFS（8 个）** —— 若目标平台已有文件系统，多为薄封装。
3. **段收集符号（6 个）** —— 链接脚本改动，容易漏但好改，且有明确自查方法。
4. **OS / 内存 / libc（25 个）** —— 目标平台通常现成，对接名字即可。
5. **歌词的 flash 直存（4 个）** —— 不要该功能可跳过。

> 注：上面这些接口的**调用方**（框架源码）已经过一轮加固，补齐了空指针、
> 缓冲区越界、除零、读盘返回值等防护，详见 `cpu/br27/tools/ui_reimpl/README.md`
> 第 9 节。移植时若某个接口返回失败，框架现在会如实往上报而不是拿脏数据继续跑。

另外**不属于本清单、但同样要带走的东西**：

- `include/` 下 37 个头文件（本目录自带）
- 资源文件与字库：`cpu/br27/tools/JL_OLED/*.res|.str|.sty`、`cpu/br27/tools/font/*.PIX|.TAB`
- 应用侧的窗口 / 控件 ID 定义：`apps/soundbox/include/ui/ui_style.h`、`style_jl02.h`
- 应用侧头文件：`apps/soundbox/include/ui/` 的 `ui_api.h`、`lcd_spi/lcd_drive.h`、
  `res_config.h`、`ui_sys_param.h`（框架源码直接 include 了它们）

## 10. 数据怎么复跑

本清单不是手写的，是从目标文件符号表算出来的。改动框架后可以这样重算：

```sh
cd <SDK 根>
NM=C:/JL/pi32/bin/llvm-nm.exe
O=objs/apps/common/ui/ui_framework

# 框架内部定义的符号
"$NM" $O/*/*.o | grep -E " [TDBWVRA] " | awk '{print $NF}' | sort -u > /tmp/def.txt
# 框架引用但自己没定义的
"$NM" $O/*/*.o | grep " U "            | awk '{print $NF}' | sort -u > /tmp/und.txt
# 二者之差 = 对外依赖
comm -23 /tmp/und.txt /tmp/def.txt

# 想知道某个符号是被哪个文件引用的:
"$NM" --print-file-name $O/*/*.o | grep " U <符号名>$"
```

> 注意 `objs/apps/common/ui/ui_framework/` 下只有**参与编译**的 39 个 `.o`；
> `ui_cpu/` 不在 `c_SRC_FILES` 里，默认不会出现在这里（这正是本清单想要的口径）。
> 若之前为跑 `verify.sh` 手动编过它们，重算前先删掉那三个 `.o`，否则会混入 IMD 的依赖。
