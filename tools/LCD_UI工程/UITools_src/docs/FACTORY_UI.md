# 原厂 ui-tools.exe 的界面（实测对照）

重建版的界面按这份对照复刻。所有内容都是把原厂 `ui-tools.exe` 跑起来、
加载 `SmallColorTFT.json` 之后截图量出来的，不是猜的。

> 复现方法：`ui-tools.exe` 的**工作目录必须是工程目录**，否则它按 CWD 去解析
> 工程里的 `lang_excel` 相对路径（`../../../UITools/多国语言_128_64.xls`），
> 找不到会弹"文件未找到"。它也**不接受命令行传工程路径**，只能从
> `打开工程(O)` 走。

## 5. 操作逻辑与限制（逐条对照）

这一节有两个依据，**官方手册优先**：

1. `tools/LCD_UI工程/doc/UI布局工具使用说明.pdf`（34 页）—— 原厂自己写的规格书，
   逐节讲了每种控件怎么建、有哪些专有属性。另有 `ui配置说明.pdf`、
   `工具快速使用说明.pdf`。
2. 把 `ui-tools.exe` 里所有 **null 结尾、UTF-8、含 2 个以上汉字** 的干净字符串
   扫出来（288 条，去掉 Qt 自带的 IDN 顶级域名表后 153 条是界面用语），
   再按它们在 `.rdata` 里的相邻关系归到各自的类里：

```
python re/scan_ui_strings.py UITools/ui-tools.exe ui_strings.txt
-> 153 条界面用语
```

提示语一律**原文照抄**，包括原厂自己的笔误（"对像"、"选请择"、"正解的文件"），
这样从原厂换过来的人看到的是同一句话，不会以为换了个工具。

### 5.1 新建的前提

| 动作 | 原厂要求 | 拦下来时说的话 |
|---|---|---|
| 新建控件（控件列表里的按钮） | 当前选中的必须是一个**布局** | `请选择一个布局或者新建一个并选中它.` |
| 新建布局（"布局"大按钮） | 当前选中的必须是一个**图层** | `请选择一个图层或者新建一个图层,并选中它.` |
| 新建图层（"图层"大按钮） | 无（直接挂在当前页上） | — |
| 建完 | 弹输入框问名字 | `请输入控件名称` |

**拖是主要手势，点是第二条路。** 手册通篇写的是拖：「点击图层并**拖动**到绘制
面板上新建一个图层」「点击并**拖动** slider 控件到布局上」。两条路的区别：

| | 挂到哪 | 位置 |
|---|---|---|
| 拖 | 松手那一点所在的容器（找不到合适的容器就拒绝，指针变禁止符号） | 松手的坐标 |

拖动时鼠标底下要跟着一个**半透明的按钮拖影**（`QDrag::setPixmap`），否则只有
指针形状变一下，用户看不出自己正在拖东西。拖影用按钮自身的渲染 —— 控件列表的
按钮是纯文字的（`control.json` 里引用的 `config\images\*.ico` 在原厂目录里
压根不存在，所以原厂按钮也没图标），拖着一个写着"垂直列表"的小方块走，
一眼就知道拖的是什么。
| 点 | 当前选中的节点（不合适就弹上面那两句话） | 模板默认位置 |

拖的落点判定会**沿父链上溯**：拖到某个控件上，会找到它所属的布局并落进去 ——
这是对的，不是 bug。真正落不下去的是所有布局之外的地方。

默认名字是 `<控件中文名>_<序号>`。这个序号**跨页全局递增，且不计页节点**：
`SmallColorTFT.json` 里页0 有 49 个非页节点（图层_0 … 文字_48），页1 的第一个
节点就叫 **图层_49**。我一开始按页各数各的，第二页新建出来的东西会和第一页重名。

### 5.2 对象树第一列显示什么

**不是直接显示 `-name`。** 原厂界面上那两个列表节点显示的是 `垂直列表_16` /
`垂直列表_25`，可它们在 json 里的 `-name` 是**裸的类型名** `"VerticalList"`
（oled 工程里还有个 `"HorizontalList"`）。也就是说 `-name` 没被正经命名过时，
原厂是拿 `caption + "_" + 序号` 现算的。照搬 `-name` 的话树上会冒出一个英文名。

规则：

```
显示名 = (-name 为空 || -name == -type || -name == -class)
         ? caption + "_" + 全局序号
         : -name                      // 用户自己起的名字原样显示
```

**说清楚不确定的地方**：能区分这两种规则的样本只有 `-name == -type` 这一种
（全部 787 个节点里只有 3 个），所以"什么算没正经命名"我取了最保守的判据。
用户自己起的名字一律不会被覆盖。

### 5.3 节点挂在哪个 json 键下

277 个节点统计出来的实际组合，**只有这四种**：

| 父 -class | 键 | 子 -class |
|---|---|---|
| ScenesScreen | `layer` | NewLayer |
| NewLayer | `layout` | NewLayout |
| NewLayout | `layout` | NewFrame / NewLayout / NewList |
| NewList | `listwidget` | NewLayout（列表的行模板） |

工程文件里**没有 `widget` 这个键**。键写错了文件仍是合法 json，但下游 QtToolBin
遍历不到那棵子树，表现是"编辑器里有这个控件，生成的 .sty 里没有"。

新建控件时是把 `control/control.json` 里那份模板**整份克隆**下来的：对照过原厂
工程文件，节点的键集合 = 模板的键集合（连空的 `"widget": []` 都留着），只多出装
孩子用的 `layout` / `listwidget`。手搭一个空壳节点会丢掉 `element_css`，也就丢掉
了几何、样式和事件。

### 5.4 属性页签上的 CSS 状态操作

一个页签 = 一个 CSS 状态 = `property[-name=="element_css"].struct` 数组里的一项。
**在页签上点右键**弹出菜单（手册 2.10 原话："右键点击菜单项的 CSS 属性_0，
选择复制添加，添加 CSS 属性_1"；原厂截图里页签下面也确实没有按钮行 ——
我一度做成了一排按钮，是自己发明的）：

| 按钮 | 做什么 |
|---|---|
| `清除` | 把当前状态清空（项还在，内容没了） |
| `复制添加` | 复制当前状态，追加到最后 |
| `复制插入` | 复制当前状态，插在它后面 |
| `删除活动项` | 删掉当前状态；只剩一个时不让删 |

留最后一个是重建版加的保险：状态数归零的控件在画布上没有 rect，在 .sty 里也没有
可写的几何，等于把控件废了。原厂在这种情况下什么行为，没有样本可看。

### 5.5 右键菜单（画布和对象树是同一套）

```
删除当前-<名字>
保存成控件
  ├ 列表(NewList) 追加：添加行/添加列、设置行高/设置列宽、设置间隔、垂直滚动、水平滚动
  └ 表格(NewGrid) 追加：添加行、添加列、单元尺寸、单元间距、设置行列
──────────
显示同类容器 / 隐藏同类容器      （子对象整体显隐，文字随状态翻）
显示 / 隐藏                      （自己，文字随状态翻）
──────────
复制
粘贴
──────────
移到顶层 / 移上一层 / 移下一层 / 移到底层
──────────
查找对像
```

页面空白处右键是另一套：`删除当前页面` / `修改背景色` / `修改背景图片`。

叠放次序就是节点在 `parent->children` 里的次序（后建的盖在上面），所以挪层就是挪
数组下标；挪完必须把**父节点**标脏，否则新次序落不到文件里。

### 5.6 粘贴的容器限制

| 情形 | 结果 |
|---|---|
| 剪贴板空 | 什么也不做 |
| 目标不是布局 | 拒绝：`当前的选中的对像不支持剪切板里的对像粘贴,请选择一个<布局>对像.` |
| 目标是布局，但内容塞不进去 | 拒绝：`当前类型容器不接受粘贴!` |
| 都合适 | 贴进去，名字自动去重 |

剪贴板存的是节点的 json 副本，不是指针 —— 源节点随时可能被删掉。粘贴时用的键按
**目标**父节点定（见 5.2），从列表的 `listwidget` 里复制一个布局贴到普通布局下
面，键要从 `listwidget` 变成 `layout`。

### 5.7 确认框

| 场合 | 标题 | 正文 | 按钮 |
|---|---|---|---|
| 删控件/布局/图层 | `删除提示` | `你真的要删除当前%1吗?删除之后不可以撤消,请选择<删除>删除.` | **删除** / 取消 |
| 删页面 | 同上，%1 = 页面 | 同上 | 同上 |
| 新建工程 | `新建工程提示` | `是否关闭当前工程,新建工程?` | 确定 / 取消 |
| 有改动没存就要关/新建/打开 | `关闭工程提示` | `当前编辑的工程有新的修改没有保存,选请择<保存>进行保存.` | 保存 / 不保存 / 取消 |
| 退出 | `退出程序` | `是否真的退出程序?` | 退出 / 取消 |

按钮文字是 `<删除>` `<保存>` 而不是 Qt 默认的 Yes/No —— 正文里点了名。这个工具
**没有撤消**，所以删除的默认焦点给"取消"。

### 5.8 数值限制

- 宽或高敲 0：拦下来，`宽高不能设置为零.`。**不能偷偷 `qMax(1,v)` 兜过去** ——
  界面上还显示 0，存进去却是 1，下次打开数字自己变了。
- **坐标可以是负的，别钳。** 我一度在拖动里把 x/y 夹到 `[0, 父级尺寸]`，理由是
  "负坐标写进 .sty 会被当无符号读"。查了固件才知道这理由是错的：

  ```c
  /* User/ui_framework/include/ui/ui_core.h */
  struct element_css { u8 align:2; u8 invisible:1; u8 z_order:5;
                       int left; int top; int width; int height; ... };
  ```

  `left`/`top` 是**有符号 int**，而且原厂自己的 `SmallColor_oled.json` 里就有
  `(0,-11)` 的控件 —— 让内容从父容器上边缘露出去是他们在用的手法。加钳制等于
  凭空多一条原厂没有的限制，还会把用户已有的负坐标改掉。已撤销，`--ops-test`
  里留了一条守着它别再回来。宽高的下限 1 保留（负宽高没有意义）。
- 整数输入框上限：`9999 内的整数`。
- 表格行列：`请输入行列整数,必需满足 (行*列>0)`。
- 列表的"行高/列宽"改的是节点上那个独立的 `sizehw` 字段，"间隔"是 `space`，
  滚动方向是 `orientation`（Vertical / Horizontal）—— 都不是控件自己的 rect。
  原厂工程里的 VerticalList 是 `sizehw=16` / `space=0`。

### 5.9 还没做到的

- **NewGrid 的行列数存在哪个键上不知道**。原厂那份工程 277 个节点里一个 NewGrid
  都没有（NewFrame 175 / NewLayout 85 / NewList 14 / NewLayer 3），`control.json`
  的模板里也只有 id / element_css / scroll / highlight_index / action，没有存行列
  数的字段。重建版先用 `rows` / `cols`，拿到带 NewGrid 的原厂工程要按样本改。
- **`保存成控件`落到 `<UITools>/control/ex/`**。原厂[全局设置]里写的是"自定义的
  模版控件目录,默认是 widgets 目录"，但原厂 UITools 目录下没有 widgets，控件确实
  是从 `control/ex/` 扫出来的（slider / vslider 就在那儿）。两说法对不上，重建版
  按**实际生效的那个**来。
- 事件动作（ActionList）的二进制布局仍未逆向，见 RE_REPORT.md 未决项。

## 6. 内容预览的判定规则（全部对着固件源码定，不是照手册猜）

画布、右栏页面视图、两个列表编辑对话框共用同一条渲染链。哪些东西画得出来、
画成什么样，规则都在固件里写死了，下面逐条记下出处 —— 以后改预览之前先看这节，
免得又"画得好看但设备上不是那样"。

### 6.1 文字控件：只有 `strpic` 的内容来自资源

`编码格式`（json 里 `-name=code`）是**固定三种**，固件 `ui_text.c` 里是硬编码
字符串比较，写别的三个分支都不匹配、屏上一片空白且不报错：

| 取值 | 内容从哪来 | 固件出处 |
|---|---|---|
| `strpic` | **资源**：`文字列表` 的 ResID → result.str 里预先光栅化好的图片串 | `ui_synthesis_oled.c:966` `id = str[0]; open_string_pic(id)` |
| `text` | **程序运行时写**（`ui_text_set_text_by_id` 等，按 ID号 找控件） | `ui_synthesis_oled.c:764` `font_open(NULL, language)` 按字库渲染 |
| `ascii` | **程序运行时写**；init 时 `attrs.str = NULL`，不写就不画 | `ui_text.c:277`、`ui_synthesis_oled.c:922` |

**`text` 下配了文字列表也显示不出那句话**：init 时 `attrs.str` 指向的是 `_str[]`，
即 **u16 的 ResID 数组**，字库把那几个字节当字符渲染出来是乱码。原厂两个工程里
19 个 `text`、4 个 `ascii` 控件的文字列表**全是空的**，正好印证。

所以预览只在 `code == "strpic"` 时画资源里的文字。`text` / `ascii` 想看排版，
用属性面板上那栏「预览文字」——它只存在工具配置里（`GlobalSettings`），
**不进工程 json、不进资源**。

### 6.2 时间 / 数字：format 是模板串，不是枚举

时间（`ui_time.c:65` `time_vsprintf`）逐字符扫：

- `Y` → **4 位**年；`M` `D` `h` `m` `s` → 各 2 位
- **其余字符原样进串**，换图时每个非数字吃一张`分隔符图片`（`delimiter[j++]`）
- 分隔符取到 `0xffff`（配的张数不够）→ **就地截断，后面整段不画**

数字（`ui_number.c:76` `number_vsprintf`）只认 `%0Nd` / `%Nd` / `%d`（N=1..9），
**最多两个**；写别的或超过两个，整个控件不显示（原厂打印 `not support yet` 后返回）。
`%Nd` 补的空格取`空格图片列表`。

**结尾的 `/` 不是结束符**。两个 vsprintf 在循环之后都无条件补终止符
（`buf[i+1]=0xff; buf[i]=0xff;`），渲染那头是 `while (id != 0x00ff && id != 0xffff)`
（`ui_synthesis_oled.c:1120`）—— 串尾总会终止，不需要写字符去结束它。
`m:s/` 能用只是因为它只配了 1 张分隔符，走到 `/` 时正好用完才停：**结果对，理由错**。
`Y/M/D` 配了 2 张分隔符，两个 `/` 都是真画出来的。

一旦给 `m:s/` 那个控件补上第 2 张分隔符图，它就会**多画一个符号**。所以工具的
格式预设一律不带结尾 `/`，并在分隔符不够时红字告警。
实测原厂工程里 oled 的 `时间_461` 用 `h:m:s` 却一张分隔符都没配，
设备上只会显示 `HH` 然后整段截断。

### 6.3 图片列表：哪一条才是"当前那条"

按"哪个参数真的指定了条目"来，实测两个工程：

| 属性 | 指定条目的是谁 | 依据 |
|---|---|---|
| `str`（文字列表） | `default` | default **209/209** 都在 list 里 |
| `normal_image`（图片列表） | `默认高亮`（`highlight`） | default **196/202** 不在 list 里，是控件模板残留 |
| 其它 piclist / arrlist | 第 1 条 | 没有任何参数指定 |

属性面板每个列表属性下面的条目下拉框**就停在预览真正画的那一条上**，
面板和画布因此永远对得上。

### 6.4 单色屏语义

见 `include/Preview.h` 抬头。三个魔数（`0x555AAA` / `0xAAA555`）来自
`ui_synthesis_oled.c`，比较是在 **RGB565** 上做的。

### 8.1 工具栏是「图标在上、文字在下」的大按钮

参照 `temp/Snipaste_2026-09-09_08-46-05.jpg`（原厂另一台机器上的同族版本）：
一排大按钮，28px 左右的彩色图标在上、中文标题在下，按钮之间是细竖线分隔符，
整条工具栏是自上而下的浅蓝灰渐变，**末尾一句蓝色状态文字**（那张图里是「编译成功」）。

重建版之前做成了 16px 小图标 + 文字在右，形状完全不是一回事。现已改成
`Qt::ToolButtonTextUnderIcon` + 28px 图标。

**踩到的坑：别给 `QToolButton` 加 `min-width`。**
样式表里写了 `min-width: 52px` 之后，`QStyleSheetStyle` 拿它当**实际宽度**用而不是
下限，每个按钮都被压成 52+padding，标题被 `QCommonStylePrivate::toolButtonElideText`
从中间截断成「新建…」。让 Qt 自己按文字算宽度就对了。

**第二个坑：按钮变宽之后一排装不下。** 重建版自己加的那几个视图控件（缩放下拉、
显示隐藏项、单独预览、画面翻页）如果直接 `tb->addAction`，会被工具栏一并撑成
大按钮，合计一千七百多像素，末尾那句状态文字被 `QToolBarLayout` 整个收进
（默认不可见的）溢出菜单，界面上一个字都看不见。

**一项都不许挪走**，所以做法是：把它们装进一个自带 `QHBoxLayout` 的 `QWidget`
里再 `tb->addWidget()`。容器里的控件不受工具栏 `ToolButtonStyle` 管，按各自
文字宽度排，省掉一半宽度。三个配套细节：

* 容器要 `setSizePolicy(QSizePolicy::Fixed, …)` —— 默认的 Preferred 会让它把
  一排用剩的宽度全吃掉，状态文字照样被顶出去；
* 状态标签用 `setMaximumWidth()` 限宽（`QWidgetItem::sizeHint()` 会按
  maximumSize 截顶，于是这一项宽度有上界，排得下），超长文字在
  `onStatusMessage()` 里加省略号、完整内容挂 tooltip；
* **不能**用 `QSizePolicy::Ignored` 去有多少用多少 —— `QWidgetItem::sizeHint()`
  遇到 Ignored 直接把宽度报 0，标签被压成零宽，同样什么都看不见。

按钮内边距 8px→5px、分隔符边距 5px→3px，一排（含状态文字）正好落在 1694 宽度内。

### 8.5 工具栏「隐藏辅助线」，以及顺藤摸出来的四个内存 bug

放大之后画布上编辑器自己画的东西比内容还显眼：控件的虚线描边、选中框、
控件名、8 个缩放手柄、像素网格。工具栏加了一个可勾选的「隐藏辅助线」，
关掉之后画面上**只剩屏上真会显示的像素**。

实现分两层，因为手柄不是控件自己的子窗口：

* `FormResizer::setShowChrome()` —— 描边/选中框/控件名，外加 8 个
  `SizeHandleRect`（它们挂在**父控件**上，要画在控件外面）
* `ScenesScreen::setShowChrome()` —— 转发给本页所有控件，并关掉像素网格
* `CanvasManager::setShowChrome()` —— 转发给所有页

验证：`UITools.exe --zoom 400 --select 3 --no-chrome --shot x.png`，
画布区的像素直方图里应当只剩点亮色和熄灭色。实测开着时 12898 个非亮/灭像素
（描边+网格+手柄），关掉之后 **0 个**。ops-test 里也加了这两条断言。

#### 加这条断言时炸出来的四个 bug（都是既有的，不是这次改坏的）

断言要抓一次画布（`ScenesScreen::grab()`），而**工具栏的「截屏」
（`CanvasManager::onSshoot()`）走的就是这一句** —— 所以这四个都是用户能踩到的。
靠 MSVC 的 AddressSanitizer（`/fsanitize=address`，见 `C:\bt\asan.bat` 那套
构建参数）拿到确切现场，不是猜的：

1. **删掉控件后，`ScenesScreen::m_forms` 里留野指针。**
   `BaseForm::onDeleteMe()` 只 `deleteLater()` 自己，不通知画布。
   → 建控件时挂 `QObject::destroyed` 自动清理（`m_forms`/`m_userHidden`/`m_selected`）。

2. **结构变了没人重建画布。** 删除会连同整棵子树一起 `delete`（`UiNode`
   析构递归删 children），但那些**子控件**的 `BaseForm` 还活着、`m_node`
   全是野指针，全链路上没有一处重建。
   → `ScenesScreen` 收到 `BaseForm::structureChanged` 时 `rebuild()`。

3. **`rebuild()` 只 `deleteLater()`，旧控件在事件循环转回来之前仍是可见子控件**，
   还会被重绘 —— 而重建的常见诱因正是"删了个节点"。
   → 先 `setSelected(false); hide(); setParent(nullptr);` 再排队销毁。
   不能直接 `delete`：`rebuild()` 常常是被控件自己的信号叫起来的。

4. **`FormResizer` 析构不带走自己的手柄。** 手柄挂在父控件上，Qt 不会跟着删，
   留在画布上、`m_target` 指着已释放的控件；画布每缩放一次 rebuild 一次，
   孤儿越攒越多。
   → `~FormResizer()` 手动删；`m_handles`/`m_target` 改 `QPointer`，
   防父控件先走时的二次释放。

修 1 的时候还自己制造过一个：`destroyed` 回调**按节点键**无条件删，而
`rebuild()` 是"旧的 deleteLater + 立刻建新的"，同一个键上已经换成新控件了 ——
回调一进来把新的那项删掉，`formFor()` 返回空指针。加了身份判断（`m_forms.value(n) != f` 就直接返回）。

还有 `ScenesScreen::~ScenesScreen()`：子控件是在 `QWidget::~QWidget()` 里删的，
那时本对象的成员**已经析构完**（顺序：本类析构体 → 本类成员 → QWidget 删子控件
→ QObject 断连），`destroyed` 回调再进来摸 `m_forms` 就是 use-after-free，
进程退出时崩。析构体是最后一个"成员还活着"的时机，在那儿把连接掐掉。

改完 ASan 下四种模式（ops-test 两个工程、对话框冒烟、json 往返、自截）
**零报错**，ops-test 从 126/108 涨到 131/113 全过。

### 8.6 「背景图片」原来根本设不上 —— 三处都不对

用户反馈"控件的背景图片设置不了，原厂可以，而且原厂是弹窗选的"。查下来
**三处**都不对，缺一处这个功能就是废的：

#### 1. 弹的窗口就不对

原厂有两个长得很像的图片对话框，靠 exe 里的字符串能分开（0xc98819 起）：

| 类 | 字符串 | 用途 |
|---|---|---|
| `ImageFileDialog` | `图片编辑`、`onAddSelectedItems/onDelSelectedItems`、`已经添加的图片数:`、上移/下移图标 | 图片列表，**多选** |
| `ImageListView` | `图片编辑(双击选中图片并更新到控件)`、`双击选中图片并更新到控件显示.`、`目录` | 背景图片，**双击单选** |

重建版这一行点开的是 `QFileDialog::getOpenFileName`（系统文件对话框），
和原厂完全不是一回事。现在改成 `ImageListView`：左「目录」树、右缩略图、
双击即选中并关闭，版式和图片列表那个一致。

#### 2. 存进去的路径形式不对（这条最致命）

工程 json 里 `background-image` 存的是**相对工程目录**的
`config/pic_lcd/v_block.bmp`（实测该字段 277 条，2 条非空，都是这个形式）。
而系统文件对话框回来的是绝对路径 —— 存进去之后：

* 预览按相对路径拼绝对路径，拼出来是错的，找不到图；
* `StyBuilder` 是拿这个字符串去 `picId` 表里查图片资源号的
  （`css` 偏移 +24），查不到就写 `0xFFFFFFFF` = 没有背景图。

也就是说：**选了也等于没选，产物里根本不带这张图**。
`ImageListView::selected()` 一律返回相对工程目录的正斜杠形式。

#### 3. 画布压根不画 background-image

`Forms.cpp` 只画了填充、内边框线、图片/文字/数字，没有背景图这一层；
右栏页面预览同理。所以就算前两条都对，用户选完图**画面上也没有任何变化**，
从现象上看就是"设置不了"。

现在 `Preview::pictureOf()` 按同一套单色判定取图，画在填充之上、内容之下
（和固件的层次一致），画布和右栏都画。

顺带：按钮上现在直接显示文件名（`背景图片: v_block.bmp`），空的时候提示
"没有背景图片，点一下选一张" —— 原来光一个"背景图片"四个字，看不出设没设。

#### 回归

ops-test 新增一节（TFT 136 项 / oled 118 项全过）：

```
[通过] 背景图片弹窗列得出图片                        —— 65 张
[通过] 双击能选中一张图                              —— config/m1.png
[通过] 弹窗给的是相对工程目录的路径，不是绝对路径      —— config/m1.png
[通过] 背景图片写得进 css
[通过] 设了背景图片，画布上真的多出点亮像素            —— 设之前 1223 -> 设之后 2434
```

### 8.7 「唯一ID号」：新建控件要自带、改完不点别处也要算数

用户报了两条，查下来第二条其实是第一条那个坑的**表象**：

> 1、新建控件，会有一个默认的不重复的 id 号的，你的是空的
> 2、新建的图层设置了 id 号后，点击导出，生成的头文件里对的 id 是没有的

#### 默认 ID 号：`BaseForm` / `BaseForm_1` / `BaseForm_2` …

原厂建出来的控件「唯一ID号」不是空的。证据两条，互相印证：

* `ui-tools.exe` 里 `'BaseForm'`(0xc94f30) 紧挨着 `'Ename is empty'`(0xc94f3b)，
  同一编译单元（上面是 `'ComProperty'` / `'CssProperty'`）里还有格式串 `'%1_%2'`；
* 用户在编辑器里新建的那一页，图层/布局拿到的正是 `BaseForm_1` / `BaseForm_2`；
  页 1 里还有个更早的裸 `BaseForm`（没后缀）和 `NewFrame_23/24/25`。

规则：`base` 没被占就用 `base`，否则 `base_1`、`base_2` 往后找，
**大小写不敏感**（`ename.h` 里的宏名是全大写的，`BaseForm` 和 `BASEFORM`
会撞成同一个宏）。实现在 `ProjectModel::uniqueEname()`，
`CompoentControls::appendChild()` 建节点时补空的（模板自带 ename 的不覆盖）。

#### 「设了 ID 号导出后头文件里没有」= 值压根没提交

先排除了导出这一侧：页 3 那个图层的 `BASEFORM_1`，本版和原厂的 `ename.h`
里都有，值也一样（`0XC494B2`）。所以不是生成漏了。

真正的原因是用户报的第三条：

> 修改属性后，如果鼠标没有点击其他地方，直接点击保存，发现参数没有保存

属性面板上所有输入框都是 **`editingFinished`** 才写回模型（和原厂一致），
而**工具栏按钮是 `Qt::NoFocus`** —— 点「保存」/「资源导出」不会让输入框失焦，
`editingFinished` 不发，刚敲进去的值还停在控件里。

修法：`EditorOps::commitPendingEdit()`（对 `QApplication::focusWidget()` 调
`clearFocus()`，一句话覆盖 QLineEdit / QSpinBox / 可编辑 QComboBox），
在**保存 / 另存为 / 资源导出 / 退出前的脏检查**四处都先调一遍。

#### 顺带抓出来的：克隆节点会复制 ID 号

新加的「ID 号全工程唯一」断言当场报了 3 个重复 —— **列表加行**是从第一行
整棵克隆的，`ename` 一起带了过来；**粘贴**同理。两个宏同名 `#define` 两次，
业务代码引用到哪一个全看运气。两处都改成走 `EditorOps::reassignEnames()`。

写这个函数时我自己又踩了一个：一开始顺着 `UiNode::parent` 往上爬去收集
已用名字 —— **爬到页节点就到头了**（页的 `parent` 是 `nullptr`），跨页的名字
扫不到，在页 0 的列表里加行分到的 `BaseForm` 和页 1/页 3 已有的撞车。
改成让 `EditorOps` 持有当前 `ProjectModel`（`CanvasManager` 构造时挂上），
去重范围覆盖整个工程。

#### 回归

```
[通过] ID 号全工程唯一（大小写不敏感）
[通过] 刚敲完还没提交时，模型里确实还是旧值      —— BT_BAT
[通过] 保存前的强制提交能把输入框里的值写进模型   —— OPSTEST_ENAME_1
```
