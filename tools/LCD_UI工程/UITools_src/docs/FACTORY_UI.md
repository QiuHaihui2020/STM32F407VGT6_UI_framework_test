# 原厂 ui-tools.exe 的界面（实测对照）

重建版的界面按这份对照复刻。所有内容都是把原厂 `ui-tools.exe` 跑起来、
加载 `SmallColorTFT.json` 之后截图量出来的，不是猜的。

> 复现方法：`ui-tools.exe` 的**工作目录必须是工程目录**，否则它按 CWD 去解析
> 工程里的 `lang_excel` 相对路径（`../../../UITools/多国语言_128_64.xls`），
> 找不到会弹"文件未找到"。它也**不接受命令行传工程路径**，只能从
> `打开工程(O)` 走。

## 5. 操作逻辑与限制（逐条对照）

这一节有两个依据，**官方手册优先**：

1. `tools/LCD_UI工程/doc/UI布局工具使用说明.pdf`（34 页）—— 原厂自己写的规格书，
   逐节讲了每种控件怎么建、有哪些专有属性。另有 `ui配置说明.pdf`、
   `工具快速使用说明.pdf`。
2. 把 `ui-tools.exe` 里所有 **null 结尾、UTF-8、含 2 个以上汉字** 的干净字符串
   扫出来（288 条，去掉 Qt 自带的 IDN 顶级域名表后 153 条是界面用语），
   再按它们在 `.rdata` 里的相邻关系归到各自的类里：

```
python re/scan_ui_strings.py UITools/ui-tools.exe ui_strings.txt
-> 153 条界面用语
```

提示语一律**原文照抄**，包括原厂自己的笔误（"对像"、"选请择"、"正解的文件"），
这样从原厂换过来的人看到的是同一句话，不会以为换了个工具。

### 5.1 新建的前提

| 动作 | 原厂要求 | 拦下来时说的话 |
|---|---|---|
| 新建控件（控件列表里的按钮） | 当前选中的必须是一个**布局** | `请选择一个布局或者新建一个并选中它.` |
| 新建布局（"布局"大按钮） | 当前选中的必须是一个**图层** | `请选择一个图层或者新建一个图层,并选中它.` |
| 新建图层（"图层"大按钮） | 无（直接挂在当前页上） | — |
| 建完 | 弹输入框问名字 | `请输入控件名称` |

**拖是主要手势，点是第二条路。** 手册通篇写的是拖：「点击图层并**拖动**到绘制
面板上新建一个图层」「点击并**拖动** slider 控件到布局上」。两条路的区别：

| | 挂到哪 | 位置 |
|---|---|---|
| 拖 | 松手那一点所在的容器（找不到合适的容器就拒绝，指针变禁止符号） | 松手的坐标 |

拖动时鼠标底下要跟着一个**半透明的按钮拖影**（`QDrag::setPixmap`），否则只有
指针形状变一下，用户看不出自己正在拖东西。拖影用按钮自身的渲染 —— 控件列表的
按钮是纯文字的（`control.json` 里引用的 `config\images\*.ico` 在原厂目录里
压根不存在，所以原厂按钮也没图标），拖着一个写着"垂直列表"的小方块走，
一眼就知道拖的是什么。
| 点 | 当前选中的节点（不合适就弹上面那两句话） | 模板默认位置 |

拖的落点判定会**沿父链上溯**：拖到某个控件上，会找到它所属的布局并落进去 ——
这是对的，不是 bug。真正落不下去的是所有布局之外的地方。

默认名字是 `<控件中文名>_<序号>`。这个序号**跨页全局递增，且不计页节点**：
`SmallColorTFT.json` 里页0 有 49 个非页节点（图层_0 … 文字_48），页1 的第一个
节点就叫 **图层_49**。我一开始按页各数各的，第二页新建出来的东西会和第一页重名。

### 5.2 对象树第一列显示什么

**不是直接显示 `-name`。** 原厂界面上那两个列表节点显示的是 `垂直列表_16` /
`垂直列表_25`，可它们在 json 里的 `-name` 是**裸的类型名** `"VerticalList"`
（oled 工程里还有个 `"HorizontalList"`）。也就是说 `-name` 没被正经命名过时，
原厂是拿 `caption + "_" + 序号` 现算的。照搬 `-name` 的话树上会冒出一个英文名。

规则：

```
显示名 = (-name 为空 || -name == -type || -name == -class)
         ? caption + "_" + 全局序号
         : -name                      // 用户自己起的名字原样显示
```

**说清楚不确定的地方**：能区分这两种规则的样本只有 `-name == -type` 这一种
（全部 787 个节点里只有 3 个），所以"什么算没正经命名"我取了最保守的判据。
用户自己起的名字一律不会被覆盖。

### 5.3 节点挂在哪个 json 键下

277 个节点统计出来的实际组合，**只有这四种**：

| 父 -class | 键 | 子 -class |
|---|---|---|
| ScenesScreen | `layer` | NewLayer |
| NewLayer | `layout` | NewLayout |
| NewLayout | `layout` | NewFrame / NewLayout / NewList |
| NewList | `listwidget` | NewLayout（列表的行模板） |

工程文件里**没有 `widget` 这个键**。键写错了文件仍是合法 json，但下游 QtToolBin
遍历不到那棵子树，表现是"编辑器里有这个控件，生成的 .sty 里没有"。

新建控件时是把 `control/control.json` 里那份模板**整份克隆**下来的：对照过原厂
工程文件，节点的键集合 = 模板的键集合（连空的 `"widget": []` 都留着），只多出装
孩子用的 `layout` / `listwidget`。手搭一个空壳节点会丢掉 `element_css`，也就丢掉
了几何、样式和事件。

### 5.4 属性页签上的 CSS 状态操作

一个页签 = 一个 CSS 状态 = `property[-name=="element_css"].struct` 数组里的一项。
**在页签上点右键**弹出菜单（手册 2.10 原话："右键点击菜单项的 CSS 属性_0，
选择复制添加，添加 CSS 属性_1"；原厂截图里页签下面也确实没有按钮行 ——
我一度做成了一排按钮，是自己发明的）：

| 按钮 | 做什么 |
|---|---|
| `清除` | 把当前状态清空（项还在，内容没了） |
| `复制添加` | 复制当前状态，追加到最后 |
| `复制插入` | 复制当前状态，插在它后面 |
| `删除活动项` | 删掉当前状态；只剩一个时不让删 |

留最后一个是重建版加的保险：状态数归零的控件在画布上没有 rect，在 .sty 里也没有
可写的几何，等于把控件废了。原厂在这种情况下什么行为，没有样本可看。

### 5.5 右键菜单（画布和对象树是同一套）

```
删除当前-<名字>
保存成控件
  ├ 列表(NewList) 追加：添加行/添加列、设置行高/设置列宽、设置间隔、垂直滚动、水平滚动
  └ 表格(NewGrid) 追加：添加行、添加列、单元尺寸、单元间距、设置行列
──────────
显示同类容器 / 隐藏同类容器      （子对象整体显隐，文字随状态翻）
显示 / 隐藏                      （自己，文字随状态翻）
──────────
复制
粘贴
──────────
移到顶层 / 移上一层 / 移下一层 / 移到底层
──────────
查找对像
```

页面空白处右键是另一套：`删除当前页面` / `修改背景色` / `修改背景图片`。

叠放次序就是节点在 `parent->children` 里的次序（后建的盖在上面），所以挪层就是挪
数组下标；挪完必须把**父节点**标脏，否则新次序落不到文件里。

### 5.6 粘贴的容器限制

| 情形 | 结果 |
|---|---|
| 剪贴板空 | 什么也不做 |
| 目标不是布局 | 拒绝：`当前的选中的对像不支持剪切板里的对像粘贴,请选择一个<布局>对像.` |
| 目标是布局，但内容塞不进去 | 拒绝：`当前类型容器不接受粘贴!` |
| 都合适 | 贴进去，名字自动去重 |

剪贴板存的是节点的 json 副本，不是指针 —— 源节点随时可能被删掉。粘贴时用的键按
**目标**父节点定（见 5.2），从列表的 `listwidget` 里复制一个布局贴到普通布局下
面，键要从 `listwidget` 变成 `layout`。

### 5.7 确认框

| 场合 | 标题 | 正文 | 按钮 |
|---|---|---|---|
| 删控件/布局/图层 | `删除提示` | `你真的要删除当前%1吗?删除之后不可以撤消,请选择<删除>删除.` | **删除** / 取消 |
| 删页面 | 同上，%1 = 页面 | 同上 | 同上 |
| 新建工程 | `新建工程提示` | `是否关闭当前工程,新建工程?` | 确定 / 取消 |
| 有改动没存就要关/新建/打开 | `关闭工程提示` | `当前编辑的工程有新的修改没有保存,选请择<保存>进行保存.` | 保存 / 不保存 / 取消 |
| 退出 | `退出程序` | `是否真的退出程序?` | 退出 / 取消 |

按钮文字是 `<删除>` `<保存>` 而不是 Qt 默认的 Yes/No —— 正文里点了名。这个工具
**没有撤消**，所以删除的默认焦点给"取消"。

### 5.8 数值限制

- 宽或高敲 0：拦下来，`宽高不能设置为零.`。**不能偷偷 `qMax(1,v)` 兜过去** ——
  界面上还显示 0，存进去却是 1，下次打开数字自己变了。
- **坐标可以是负的，别钳。** 我一度在拖动里把 x/y 夹到 `[0, 父级尺寸]`，理由是
  "负坐标写进 .sty 会被当无符号读"。查了固件才知道这理由是错的：

  ```c
  /* User/ui_framework/include/ui/ui_core.h */
  struct element_css { u8 align:2; u8 invisible:1; u8 z_order:5;
                       int left; int top; int width; int height; ... };
  ```

  `left`/`top` 是**有符号 int**，而且原厂自己的 `SmallColor_oled.json` 里就有
  `(0,-11)` 的控件 —— 让内容从父容器上边缘露出去是他们在用的手法。加钳制等于
  凭空多一条原厂没有的限制，还会把用户已有的负坐标改掉。已撤销，`--ops-test`
  里留了一条守着它别再回来。宽高的下限 1 保留（负宽高没有意义）。
- 整数输入框上限：`9999 内的整数`。
- 表格行列：`请输入行列整数,必需满足 (行*列>0)`。
- 列表的"行高/列宽"改的是节点上那个独立的 `sizehw` 字段，"间隔"是 `space`，
  滚动方向是 `orientation`（Vertical / Horizontal）—— 都不是控件自己的 rect。
  原厂工程里的 VerticalList 是 `sizehw=16` / `space=0`。

### 5.9 还没做到的

- **NewGrid 的行列数存在哪个键上不知道**。原厂那份工程 277 个节点里一个 NewGrid
  都没有（NewFrame 175 / NewLayout 85 / NewList 14 / NewLayer 3），`control.json`
  的模板里也只有 id / element_css / scroll / highlight_index / action，没有存行列
  数的字段。重建版先用 `rows` / `cols`，拿到带 NewGrid 的原厂工程要按样本改。
- **`保存成控件`落到 `<UITools>/control/ex/`**。原厂[全局设置]里写的是"自定义的
  模版控件目录,默认是 widgets 目录"，但原厂 UITools 目录下没有 widgets，控件确实
  是从 `control/ex/` 扫出来的（slider / vslider 就在那儿）。两说法对不上，重建版
  按**实际生效的那个**来。
- 事件动作（ActionList）的二进制布局仍未逆向，见 RE_REPORT.md 未决项。

## 6. 内容预览的判定规则（全部对着固件源码定，不是照手册猜）

画布、右栏页面视图、两个列表编辑对话框共用同一条渲染链。哪些东西画得出来、
画成什么样，规则都在固件里写死了，下面逐条记下出处 —— 以后改预览之前先看这节，
免得又"画得好看但设备上不是那样"。

### 6.1 文字控件：只有 `strpic` 的内容来自资源

`编码格式`（json 里 `-name=code`）是**固定三种**，固件 `ui_text.c` 里是硬编码
字符串比较，写别的三个分支都不匹配、屏上一片空白且不报错：

| 取值 | 内容从哪来 | 固件出处 |
|---|---|---|
| `strpic` | **资源**：`文字列表` 的 ResID → result.str 里预先光栅化好的图片串 | `ui_synthesis_oled.c:966` `id = str[0]; open_string_pic(id)` |
| `text` | **程序运行时写**（`ui_text_set_text_by_id` 等，按 ID号 找控件） | `ui_synthesis_oled.c:764` `font_open(NULL, language)` 按字库渲染 |
| `ascii` | **程序运行时写**；init 时 `attrs.str = NULL`，不写就不画 | `ui_text.c:277`、`ui_synthesis_oled.c:922` |

**`text` 下配了文字列表也显示不出那句话**：init 时 `attrs.str` 指向的是 `_str[]`，
即 **u16 的 ResID 数组**，字库把那几个字节当字符渲染出来是乱码。原厂两个工程里
19 个 `text`、4 个 `ascii` 控件的文字列表**全是空的**，正好印证。

所以预览只在 `code == "strpic"` 时画资源里的文字。`text` / `ascii` 想看排版，
用属性面板上那栏「预览文字」——它只存在工具配置里（`GlobalSettings`），
**不进工程 json、不进资源**。

### 6.2 时间 / 数字：format 是模板串，不是枚举

时间（`ui_time.c:65` `time_vsprintf`）逐字符扫：

- `Y` → **4 位**年；`M` `D` `h` `m` `s` → 各 2 位
- **其余字符原样进串**，换图时每个非数字吃一张`分隔符图片`（`delimiter[j++]`）
- 分隔符取到 `0xffff`（配的张数不够）→ **就地截断，后面整段不画**

数字（`ui_number.c:76` `number_vsprintf`）只认 `%0Nd` / `%Nd` / `%d`（N=1..9），
**最多两个**；写别的或超过两个，整个控件不显示（原厂打印 `not support yet` 后返回）。
`%Nd` 补的空格取`空格图片列表`。

**结尾的 `/` 不是结束符**。两个 vsprintf 在循环之后都无条件补终止符
（`buf[i+1]=0xff; buf[i]=0xff;`），渲染那头是 `while (id != 0x00ff && id != 0xffff)`
（`ui_synthesis_oled.c:1120`）—— 串尾总会终止，不需要写字符去结束它。
`m:s/` 能用只是因为它只配了 1 张分隔符，走到 `/` 时正好用完才停：**结果对，理由错**。
`Y/M/D` 配了 2 张分隔符，两个 `/` 都是真画出来的。

一旦给 `m:s/` 那个控件补上第 2 张分隔符图，它就会**多画一个符号**。所以工具的
格式预设一律不带结尾 `/`，并在分隔符不够时红字告警。
实测原厂工程里 oled 的 `时间_461` 用 `h:m:s` 却一张分隔符都没配，
设备上只会显示 `HH` 然后整段截断。

### 6.3 图片列表：哪一条才是"当前那条"

按"哪个参数真的指定了条目"来，实测两个工程：

| 属性 | 指定条目的是谁 | 依据 |
|---|---|---|
| `str`（文字列表） | `default` | default **209/209** 都在 list 里 |
| `normal_image`（图片列表） | `默认高亮`（`highlight`） | default **196/202** 不在 list 里，是控件模板残留 |
| 其它 piclist / arrlist | 第 1 条 | 没有任何参数指定 |

属性面板每个列表属性下面的条目下拉框**就停在预览真正画的那一条上**，
面板和画布因此永远对得上。

### 6.4 单色屏语义

见 `include/Preview.h` 抬头。三个魔数（`0x555AAA` / `0xAAA555`）来自
`ui_synthesis_oled.c`，比较是在 **RGB565** 上做的。

### 8.1 工具栏是「图标在上、文字在下」的大按钮

参照 `temp/Snipaste_2026-09-09_08-46-05.jpg`（原厂另一台机器上的同族版本）：
一排大按钮，28px 左右的彩色图标在上、中文标题在下，按钮之间是细竖线分隔符，
整条工具栏是自上而下的浅蓝灰渐变，**末尾一句蓝色状态文字**（那张图里是「编译成功」）。

重建版之前做成了 16px 小图标 + 文字在右，形状完全不是一回事。现已改成
`Qt::ToolButtonTextUnderIcon` + 28px 图标。

**踩到的坑：别给 `QToolButton` 加 `min-width`。**
样式表里写了 `min-width: 52px` 之后，`QStyleSheetStyle` 拿它当**实际宽度**用而不是
下限，每个按钮都被压成 52+padding，标题被 `QCommonStylePrivate::toolButtonElideText`
从中间截断成「新建…」。让 Qt 自己按文字算宽度就对了。

**第二个坑：按钮变宽之后一排装不下。** 重建版自己加的那几个视图控件（缩放下拉、
显示隐藏项、单独预览、画面翻页）如果直接 `tb->addAction`，会被工具栏一并撑成
大按钮，合计一千七百多像素，末尾那句状态文字被 `QToolBarLayout` 整个收进
（默认不可见的）溢出菜单，界面上一个字都看不见。

**一项都不许挪走**，所以做法是：把它们装进一个自带 `QHBoxLayout` 的 `QWidget`
里再 `tb->addWidget()`。容器里的控件不受工具栏 `ToolButtonStyle` 管，按各自
文字宽度排，省掉一半宽度。三个配套细节：

* 容器要 `setSizePolicy(QSizePolicy::Fixed, …)` —— 默认的 Preferred 会让它把
  一排用剩的宽度全吃掉，状态文字照样被顶出去；
* 状态标签用 `setMaximumWidth()` 限宽（`QWidgetItem::sizeHint()` 会按
  maximumSize 截顶，于是这一项宽度有上界，排得下），超长文字在
  `onStatusMessage()` 里加省略号、完整内容挂 tooltip；
* **不能**用 `QSizePolicy::Ignored` 去有多少用多少 —— `QWidgetItem::sizeHint()`
  遇到 Ignored 直接把宽度报 0，标签被压成零宽，同样什么都看不见。

按钮内边距 8px→5px、分隔符边距 5px→3px，一排（含状态文字）正好落在 1694 宽度内。

### 8.5 工具栏「隐藏辅助线」，以及顺藤摸出来的四个内存 bug

放大之后画布上编辑器自己画的东西比内容还显眼：控件的虚线描边、选中框、
控件名、8 个缩放手柄、像素网格。工具栏加了一个可勾选的「隐藏辅助线」，
关掉之后画面上**只剩屏上真会显示的像素**。

实现分两层，因为手柄不是控件自己的子窗口：

* `FormResizer::setShowChrome()` —— 描边/选中框/控件名，外加 8 个
  `SizeHandleRect`（它们挂在**父控件**上，要画在控件外面）
* `ScenesScreen::setShowChrome()` —— 转发给本页所有控件，并关掉像素网格
* `CanvasManager::setShowChrome()` —— 转发给所有页

验证：`UITools.exe --zoom 400 --select 3 --no-chrome --shot x.png`，
画布区的像素直方图里应当只剩点亮色和熄灭色。实测开着时 12898 个非亮/灭像素
（描边+网格+手柄），关掉之后 **0 个**。ops-test 里也加了这两条断言。

#### 加这条断言时炸出来的四个 bug（都是既有的，不是这次改坏的）

断言要抓一次画布（`ScenesScreen::grab()`），而**工具栏的「截屏」
（`CanvasManager::onSshoot()`）走的就是这一句** —— 所以这四个都是用户能踩到的。
靠 MSVC 的 AddressSanitizer（`/fsanitize=address`，见 `C:\bt\asan.bat` 那套
构建参数）拿到确切现场，不是猜的：

1. **删掉控件后，`ScenesScreen::m_forms` 里留野指针。**
   `BaseForm::onDeleteMe()` 只 `deleteLater()` 自己，不通知画布。
   → 建控件时挂 `QObject::destroyed` 自动清理（`m_forms`/`m_userHidden`/`m_selected`）。

2. **结构变了没人重建画布。** 删除会连同整棵子树一起 `delete`（`UiNode`
   析构递归删 children），但那些**子控件**的 `BaseForm` 还活着、`m_node`
   全是野指针，全链路上没有一处重建。
   → `ScenesScreen` 收到 `BaseForm::structureChanged` 时 `rebuild()`。

3. **`rebuild()` 只 `deleteLater()`，旧控件在事件循环转回来之前仍是可见子控件**，
   还会被重绘 —— 而重建的常见诱因正是"删了个节点"。
   → 先 `setSelected(false); hide(); setParent(nullptr);` 再排队销毁。
   不能直接 `delete`：`rebuild()` 常常是被控件自己的信号叫起来的。

4. **`FormResizer` 析构不带走自己的手柄。** 手柄挂在父控件上，Qt 不会跟着删，
   留在画布上、`m_target` 指着已释放的控件；画布每缩放一次 rebuild 一次，
   孤儿越攒越多。
   → `~FormResizer()` 手动删；`m_handles`/`m_target` 改 `QPointer`，
   防父控件先走时的二次释放。

修 1 的时候还自己制造过一个：`destroyed` 回调**按节点键**无条件删，而
`rebuild()` 是"旧的 deleteLater + 立刻建新的"，同一个键上已经换成新控件了 ——
回调一进来把新的那项删掉，`formFor()` 返回空指针。加了身份判断（`m_forms.value(n) != f` 就直接返回）。

还有 `ScenesScreen::~ScenesScreen()`：子控件是在 `QWidget::~QWidget()` 里删的，
那时本对象的成员**已经析构完**（顺序：本类析构体 → 本类成员 → QWidget 删子控件
→ QObject 断连），`destroyed` 回调再进来摸 `m_forms` 就是 use-after-free，
进程退出时崩。析构体是最后一个"成员还活着"的时机，在那儿把连接掐掉。

改完 ASan 下四种模式（ops-test 两个工程、对话框冒烟、json 往返、自截）
**零报错**，ops-test 从 126/108 涨到 131/113 全过。

### 8.6 「背景图片」原来根本设不上 —— 三处都不对

用户反馈"控件的背景图片设置不了，原厂可以，而且原厂是弹窗选的"。查下来
**三处**都不对，缺一处这个功能就是废的：

#### 1. 弹的窗口就不对

原厂有两个长得很像的图片对话框，靠 exe 里的字符串能分开（0xc98819 起）：

| 类 | 字符串 | 用途 |
|---|---|---|
| `ImageFileDialog` | `图片编辑`、`onAddSelectedItems/onDelSelectedItems`、`已经添加的图片数:`、上移/下移图标 | 图片列表，**多选** |
| `ImageListView` | `图片编辑(双击选中图片并更新到控件)`、`双击选中图片并更新到控件显示.`、`目录` | 背景图片，**双击单选** |

重建版这一行点开的是 `QFileDialog::getOpenFileName`（系统文件对话框），
和原厂完全不是一回事。现在改成 `ImageListView`：左「目录」树、右缩略图、
双击即选中并关闭，版式和图片列表那个一致。

#### 2. 存进去的路径形式不对（这条最致命）

工程 json 里 `background-image` 存的是**相对工程目录**的
`config/pic_lcd/v_block.bmp`（实测该字段 277 条，2 条非空，都是这个形式）。
而系统文件对话框回来的是绝对路径 —— 存进去之后：

* 预览按相对路径拼绝对路径，拼出来是错的，找不到图；
* `StyBuilder` 是拿这个字符串去 `picId` 表里查图片资源号的
  （`css` 偏移 +24），查不到就写 `0xFFFFFFFF` = 没有背景图。

也就是说：**选了也等于没选，产物里根本不带这张图**。
`ImageListView::selected()` 一律返回相对工程目录的正斜杠形式。

#### 3. 画布压根不画 background-image

`Forms.cpp` 只画了填充、内边框线、图片/文字/数字，没有背景图这一层；
右栏页面预览同理。所以就算前两条都对，用户选完图**画面上也没有任何变化**，
从现象上看就是"设置不了"。

现在 `Preview::pictureOf()` 按同一套单色判定取图，画在填充之上、内容之下
（和固件的层次一致），画布和右栏都画。

顺带：按钮上现在直接显示文件名（`背景图片: v_block.bmp`），空的时候提示
"没有背景图片，点一下选一张" —— 原来光一个"背景图片"四个字，看不出设没设。

#### 回归

ops-test 新增一节（TFT 136 项 / oled 118 项全过）：

```
[通过] 背景图片弹窗列得出图片                        —— 65 张
[通过] 双击能选中一张图                              —— config/m1.png
[通过] 弹窗给的是相对工程目录的路径，不是绝对路径      —— config/m1.png
[通过] 背景图片写得进 css
[通过] 设了背景图片，画布上真的多出点亮像素            —— 设之前 1223 -> 设之后 2434
```

### 8.7 「唯一ID号」：新建控件要自带、改完不点别处也要算数

用户报了两条，查下来第二条其实是第一条那个坑的**表象**：

> 1、新建控件，会有一个默认的不重复的 id 号的，你的是空的
> 2、新建的图层设置了 id 号后，点击导出，生成的头文件里对的 id 是没有的

#### 默认 ID 号：`BaseForm` / `BaseForm_1` / `BaseForm_2` …

原厂建出来的控件「唯一ID号」不是空的。证据两条，互相印证：

* `ui-tools.exe` 里 `'BaseForm'`(0xc94f30) 紧挨着 `'Ename is empty'`(0xc94f3b)，
  同一编译单元（上面是 `'ComProperty'` / `'CssProperty'`）里还有格式串 `'%1_%2'`；
* 用户在编辑器里新建的那一页，图层/布局拿到的正是 `BaseForm_1` / `BaseForm_2`；
  页 1 里还有个更早的裸 `BaseForm`（没后缀）和 `NewFrame_23/24/25`。

规则：`base` 没被占就用 `base`，否则 `base_1`、`base_2` 往后找，
**大小写不敏感**（`ename.h` 里的宏名是全大写的，`BaseForm` 和 `BASEFORM`
会撞成同一个宏）。实现在 `ProjectModel::uniqueEname()`，
`CompoentControls::appendChild()` 建节点时补空的（模板自带 ename 的不覆盖）。

#### 「设了 ID 号导出后头文件里没有」= 值压根没提交

先排除了导出这一侧：页 3 那个图层的 `BASEFORM_1`，本版和原厂的 `ename.h`
里都有，值也一样（`0XC494B2`）。所以不是生成漏了。

真正的原因是用户报的第三条：

> 修改属性后，如果鼠标没有点击其他地方，直接点击保存，发现参数没有保存

属性面板上所有输入框都是 **`editingFinished`** 才写回模型（和原厂一致），
而**工具栏按钮是 `Qt::NoFocus`** —— 点「保存」/「资源导出」不会让输入框失焦，
`editingFinished` 不发，刚敲进去的值还停在控件里。

修法：`EditorOps::commitPendingEdit()`（对 `QApplication::focusWidget()` 调
`clearFocus()`，一句话覆盖 QLineEdit / QSpinBox / 可编辑 QComboBox），
在**保存 / 另存为 / 资源导出 / 退出前的脏检查**四处都先调一遍。

#### 顺带抓出来的：克隆节点会复制 ID 号

新加的「ID 号全工程唯一」断言当场报了 3 个重复 —— **列表加行**是从第一行
整棵克隆的，`ename` 一起带了过来；**粘贴**同理。两个宏同名 `#define` 两次，
业务代码引用到哪一个全看运气。两处都改成走 `EditorOps::reassignEnames()`。

写这个函数时我自己又踩了一个：一开始顺着 `UiNode::parent` 往上爬去收集
已用名字 —— **爬到页节点就到头了**（页的 `parent` 是 `nullptr`），跨页的名字
扫不到，在页 0 的列表里加行分到的 `BaseForm` 和页 1/页 3 已有的撞车。
改成让 `EditorOps` 持有当前 `ProjectModel`（`CanvasManager` 构造时挂上），
去重范围覆盖整个工程。

#### 回归

ops-test 新增四条，TFT **141 项** / oled **131 项** 全过：

```
[通过] 新建控件自带默认 ID 号（不是空的）        —— BaseForm_10
[通过] ID 号全工程唯一（大小写不敏感）
[通过] 刚敲完还没提交时，模型里确实还是旧值      —— BT_BAT
[通过] 保存前的强制提交能把输入框里的值写进模型   —— OPSTEST_ENAME_1
```

### 8.8 控件参数的取值范围：原厂是数据驱动的

用户报「你做的参数没有任何限制」。原厂不是把范围写死在代码里，而是**写在
`control/control.json` 的属性上**，界面按它建编辑器。两条提示语能佐证
（exe 里存的是 UTF-8，不是 UTF-16）：

```
0xC94DE8  "请输入%1~%2的整数"       —— 属性写了 min/max 时用它
0xC94E44  "请输入 0~9999 内的整数"   —— 没写时的兜底
```

`control.json` 一共 183 条属性，带约束的全部列在这儿：

| 类型 | 属性 | 约束 |
|---|---|---|
| int8 | `highlight` / `z_order` / `highlight_index` | min=0 max=128 |
| int16 | `cent_x` / `cent_y` | min=0 max=32768 |
| text-str | `source`(数据源) / `code`(编码格式) | maxlength=8 |
| text-str | `format`(格式) | maxlength=16 |
| text-pic | `str`(文字列表) | maxlength=100 |
| piclist | `normal_image`(图片列表) | maxlength=30 |
| piclist | `image` / `charge_image`(电量/充电图片列表) | maxlength=0（不限） |
| arrlist | `number` / `delimiter` | maxlength=10 |
| arrlist | `space`(空格图片列表) | maxlength=2 |

#### 改法

新增 `applyIntRange()`，所有整数编辑器统一走它：属性写了 `min`/`max` 就用它的，
没写就按声明的类型兜底。之前本版的数字框一律 ±9999 / ±99999，等于没限 ——
往 int8 字段里写 30000 也收，生成资源时被截断成别的数。

一条**本版自己加的**：没写 `min`/`max` 时再按声明类型收一道
（`int8` 0~255、`int16` 0~32768）。原厂那 5 个 int8/int16 属性都写了 min/max，
所以这一条在原厂数据上是**空操作**，只在自定义控件（`control/ex`）漏写时兜底。

> **位置坐标那四个框不在这套规则里**。`control.json` 的 `rect` 属性
> **没有** min/max，范围是运行时按父容器算的。当初这里凭工程数据猜了一套
> （宽高下限 1、X/Y 一律 ±9999），是错的 —— 真规则见第 10 节，
> 已经从 exe 里反出来了。

#### 回归

ops-test 这一组现在是 TFT **150 项** / oled **140 项** 全过：

```

[通过] z轴坐标按模板限成 0~128（int8）
[通过] 容器(NewLayout/NewLayer)：宽<=父宽、高<=父高    —— 宽上限 16(父 16)
```

## 9. 怎么让原厂工具**当场再跑一遍**（对拍方法学）

存档产物只有一份，"我们错了"和"原厂本来就每次不一样"分不开；而且存档是在
另一台机器（盘符 `M:`）上生成的，路径注释带来几千处无关文本差异。所以这一轮
的做法是：

1. 把整棵 `UI工程`（`UITools` + 工程目录）**复制到临时目录**，
   例如 `C:\bt\facexp`。原厂目录只读，一个字节都不碰。
2. 在副本里 `Start-Process` 启动 `UITools\QtToolBin.exe`，工作目录设成
   `…\project`（它靠 `config/ini/project.ini` 找工程）。
3. **只对那一个窗口 `PostMessage(WM_KEYDOWN/UP, VK_F5)`**，
   不要用 `SendKeys`/`AppActivate` —— 那会抢焦点，按键可能落到用户正在用的
   窗口上。用 `$proc.MainWindowHandle` 拿句柄，精确投递。
4. 等 15 秒（314 张图那份大约 10 秒跑完），把产物拷走，`Stop-Process`。
5. 重复 2~4 若干遍。**跑三遍**才能把随机项识别出来。

原厂 `QtToolBin.exe` 是 Qt 5.9.3 静态链接的 i386 程序，副本里不需要额外 DLL。

这一套下来直接定案了四件靠单份存档永远看不出来的事，见
`FILE_FORMATS.md` 的 10.6 ~ 10.11：逐格字体表 `Resbuilder.dat`、
文字光栅化的三条细则、`dwLength` 公式、以及原厂三处 `QSet` 随机序。

> **注意**：`ui_128_64_JL02` 里 `.gitignore` 掉的那些产物
> （`result.*` / `project.bin` / `debug.txt` …）随时可能被任何一次运行覆盖，
> 拿它当"原厂参考"是有风险的 —— 很可能是本版工具自己生成的，对拍会变成自证。
> 要参考就用上面这套现造一份。

## 10. 位置坐标的取值范围（从 exe 反出来的，不是从数据猜的）

用户反馈"布局能设成超过图层的尺寸"。之前那版是拿工程数据反推规则的，
数据里没出现过的组合就漏了。这次直接反汇编。

### 10.1 怎么找到的

1. 已知两句提示语的文件偏移（UTF-8，不是 UTF-16）：
   `请输入%1~%2的整数` @0xC94DE8、`请输入 0~9999 内的整数` @0xC94E44。
   转成 VA（`.rdata` 文件 0xC94200 → VA 0x1096000）再在 `.text` 里找 4 字节引用。
2. 0x0040C283 那段把 `0x270F`(9999) 传给 `0x0069E2B0`，随后 `0x0069DF40`
   收一个整数 —— 于是认出 **0x69E2B0 = QSpinBox::setMaximum**、
   **0x69E230 = setMinimum**、**0x69DF40 = setValue**。
3. 拿这三个地址在应用代码段（0x401000~0x470000，Qt 静态库在更高地址）里
   扫调用点，扫出 0x00424C4F/C60/C89/CA8 四个 `setMaximum` 参数是**算出来的** ——
   那就是 rect 编辑器。函数入口 **0x00424AC0**。
4. 四个 spin 在对象里的偏移，靠 0x00424DC0 那段填值的代码定死：
   `[+0x18]=X  [+0x1C]=Y  [+0x20]=宽  [+0x24]=高`
   （那段把 QRect 的 x1/y1/x2/y2 换算成 x/y/w/h 再 setValue，一一对得上）。

### 10.2 规则本身

```c
// 无条件，先做
宽.setMaximum(父宽);
高.setMaximum(父高);
// 宽/高的 setMinimum 一次都没调 —— QSpinBox 默认下限就是 0，所以宽高可以填 0

if (自身类型 == NewLayout(3) || 自身类型 == NewLayer(4)) {
    X.setMaximum(999);   Y.setMaximum(999);
    X.setMinimum(-999);  Y.setMinimum(-999);
} else {
    X.setMaximum(父宽 - 自身宽);   X.setMinimum(0);
    Y.setMaximum(父高 - 自身高);   Y.setMinimum(0);
}
```

类型码来自 `UITools/config/ini/option.ini` 的 `[Control]` 段：
`NewLayout=3`、`NewLayer=4`，而 `VerticalList/HorizontalList/NewGrid=5`
—— **列表本身走的是下面那条**（叶子分支）。

判据是 `sub eax,3; cmp eax,1; jbe`，即"类型在 {3,4} 里"。同一个
`[对象+0x90]` 字段在应用代码里被拿来和 3 / 4 比了 17 处，确认它就是类型码。

### 10.3 为什么容器的 X/Y 反而放开

**垂直列表的行就是 NewLayout**。原厂工程里列表行排到 `y=96` 而父容器只有
48 高 —— 把 y 钳进父容器，列表就没法多于一屏。所以这不是"宽松处理"，
是原厂必须这么写。三份原厂工程 464 个容器 rect 里：

| 检查 | 违反数 |
|---|---|
| 宽 > 父宽 | 0 |
| 高 > 父高 | 0 |
| x < 0 / y < 0 | 0 |
| y + 高 > 父高 | 93（全是列表行） |

和上面的规则严丝合缝。

### 10.4 叶子控件的两个反例

`图片_232 (0,-11,128x75)` 在 128x64 的布局里、`文字_242 (64,0,64x25)` 在
128x16 的布局里 —— 按叶子分支这两个值都敲不进去。它们只能是**画布上拖出来的**
（拖动那条路原厂不钳，本版也不钳，见 ops-test 第 14 条），或者是更早版本的工具留下的。
830 个叶子 rect 里就这 5 个，其余全部符合。

### 10.5 有一条**没有**照抄

同一个函数在类型分叉之前，还对四个 spin 调了
`QWidget::setEnabled((类型-3) > 1)`（`0x777B50`，函数体是
`setAttribute(WA_ForceDisabled=0x20, !enable)` + `d->setEnabled_helper()`，
确认是 setEnabled）。按字面读，**NewLayout / NewLayer 的四个几何框在原厂是灰的**。

本版没有照抄这一条，原因：

* 用户描述的原厂行为是"布局大小**不能超过** 128×64"，不是"改不了"；
* 灰掉会直接拿掉一个功能，万一读错了代价太大；
* 反过来（不灰）最多是比原厂宽松一点，不会让人做不了事。

这条留着等确认。要照抄的话，就是在 `Position::setBounds()` 里对
`container == true` 的情况把四个框 `setEnabled(false)`。

## 11. 右栏第二列：当前页的布局预览（本版新增，原厂没有）

### 为什么加

一页里的**顶层布局**是互斥的整屏画面，运行时只显示其中一个，其余全是
`invisible=true`。画布和右栏的页面预览都按"默认隐藏就不画"来走，于是
**绝大多数布局在编辑器里根本看不见**。实测两个真实工程：

| 工程 | 顶层布局 | 默认隐藏 | 看得见 |
|---|---|---|---|
| TFT | 21 | 17（81%） | 4 |
| oled | 43 | 32（74%） | 11 |

oled 的页 7 有 9 个布局，只有 1 个看得见。原来要看别的只能用工具栏
「当前画面」下拉框一个个切 —— 而下拉框里是 `布局_285` 这种名字，
**看名字认不出是哪个画面**，只能挨个切过去试。

### 做成什么样

右栏拆成并排两列，**布局在左、页面在右**，中间夹一个大括号：

```
┌──────────────┬────┬──────────────┐
│  当前页布局  │    │     页面     │
│ [布局_1]  当前 ⎫  │  [页面_0] ◄──┐   ← 箭头指着当前页
│ [布局_11] 隐藏 ⎬──┼──────────────┘
│ [布局_14] 隐藏 ⎪  │  [页面_1]    │
│ [布局_23] 隐藏 ⎭  │  [页面_2]    │
└──────────────┴────┴──────────────┘
```

大括号（`LayoutBrace`，30px 宽）把整列布局括起来，**尖端指向**页面列里
当前那一页 —— 说明这一列是从那一页来的。几何全是现算的：

* 跨度 = 布局列第一项到最后一项的可视矩形（按视口裁）**并上**当前页那一行；
* 尖端的 y = 页面列当前项的中心，滚出视口就贴边、并把整个括号改成灰色
  （这时尖端指不到真东西上，不该再用高亮色）。

**尖端够不着当前页时，让括号自己伸长。** 这里改了两版：

1. 第一版把尖端 `qBound` 在布局项的上下沿之间（理由是括号得抱住布局，
   尖跑出去形状就歪）。结果布局只有 1 张、当前页却在第 4 页时，页面那一行
   远在布局范围之外，尖端被钳回去，**指向了空白**。
2. 第二版改成"括号只抱布局 + 够不着时引一条折线过去"。功能对了，但那条折线
   很碎，不好看。
3. 现在这版：**跨度 = 布局范围 ∪ 当前页那一行**。够不着时括号顺势把中间那段
   空位一起括进去，尖端永远落在跨度里，形状始终是一个正常的大括号，不用引线。
   `kMinHalf = 16` 保证尖端两侧各留出画勾的余量，否则会退化成一个尖角。

尖端是**数学大括号那个锐角**，不是外挂的三角箭头。做法：靠近尖端的控制点在
竖直方向收紧（`hook * 0.15`），切线就从水平变成斜向，上下两段以锐角交汇；
画笔配 `Qt::MiterJoin`，圆角接头会把尖磨平。

两列任意一个滚动、换页、换选中，`update()` 一下就自洽，不缓存任何坐标。

> **坑**：跨控件换算坐标不能用 `QWidget::mapTo(target, ...)` —— 它只认**祖先**。
> 大括号和两个列表是兄弟，第一版这么写直接 0xC0000005 崩在 paintEvent 里，
> 而且当时的测试只建不画，一条都没报。改走 `mapToGlobal` / `mapFromGlobal`，
> 并给 ops-test 加了一条 `m_pages->grab()` 强制走一遍 paintEvent。

* 每张都是 128x64 原尺寸，和左列页面预览同一套渲染（`PagePreview`），
  所以右列看到的就是画布看到的。
* 点一张 = `CanvasManager::gotoScreen(i)`，和「当前画面」下拉框**走同一条路**，
  两边永远同步。
* 每张下面一行状态。这里踩过一次：一开始写成「当前 / 默认隐藏 / 空」三选一，
  把两件**互不相干**的事挤成了一条：

  | | 含义 | 由谁决定 |
  |---|---|---|
  | 会显示 / 默认隐藏 | 设备上显不显示 | `isDefaultHidden()`，没隐藏的**全都**会显示、叠在一起 |
  | 当前 | 编辑器现在聚焦哪个 | `currentScreenIndex()`，和设备行为无关 |

  三选一的写法下，"不是当前、又没隐藏"的那些就落进空白，看的人只能猜
  （点一个隐藏布局让它变成「当前」，原来那个会显示的马上就变成空白）。
  现在两件事分开写：`当前 · 会显示` / `会显示` / `默认隐藏`，没有哑状态。

### 三个取舍

1. **只放顶层布局**，不放嵌套的。嵌套的算上去一页最多 43 个，其中 34 个是
   列表的行（128x16、长得都一样），会把有用的那 9 张淹掉。
2. **`forceRoot`**：`PagePreview` 多了一个开关，画某个布局时忽略它自己的
   "默认隐藏"，但**子控件的隐藏照旧生效** —— 要看的是"这个画面显示出来时
   长什么样"，而不是"把所有东西都摊开"。
3. **节点集合没变就只挪标记**，不重建控件。`onNodeSelected` 每次选中都会调
   `reloadLayouts()`，每次重建 9 个预览太浪费。

### 宽度

右栏从 255 加到 374（两个 128 宽的预览 + 中间 34px 的大括号，
括号里要同时放得下尖端和引线的拐弯）。中间画布还剩 830 出头，
128x64 的页面就算放到 400% 也才 512，够用。

## 12. 「烧进去整屏不显示」：工具自己建的节点漏了属性

用户实测：页 3 的布局加了背景图片，导出烧录后**整屏什么都没有**，同样的配置
用原厂工具就能显示。

### 查下来是什么

拿用户那份 `ui_128_64_JL02_rebuilt` 的产物直接读 `.sty`：

```
页0 首控件 css: 宽=10000 高=10000
页1 首控件 css: 宽=10000 高=10000
页2 首控件 css: 宽=10000 高=10000
页3 首控件 css: 宽=0     高=0      ← 零尺寸
```

css 里的左/上/宽/高是**万分比**，全 0 就是零尺寸，固件照着画等于什么都不画。
和背景图片没关系 —— 那一页的**所有**控件都是 0。

再比工程 json，页 3 的节点少了 `property` 键（还多出个 `version`）：

```
原厂建的页: ['-class','-name','-type','caption','layer','property']
                property=[{"rect": {"height":64,"width":128,"x":1,"y":1}}]
我们建的页: ['-class','-name','-type','caption','layer','version']   ← 没有 property
```

`CanvasManager::onCreateNewScenesScreen()` 只设了内存里的 `UiNode::rect`，
**没有建对应的 property**。存盘写出去的是 props，于是那一页连尺寸都没存进去；
重新打开后 `StyBuilder::rectOf(页)` 取不到父矩形，那一页所有控件的 css
几何全留 0。

**为什么一路没人报错**：编辑器画布对无效 rect 有 128x64 的兜底，界面上看着
完全正常；生成器那边取不到父矩形就静默跳过、留 0。从编辑到烧录没有任何一处
出声。

### 顺藤摸出的第二处

按同样的思路查其它建节点的路径，`ProjectModel::createDefault()`（「新建工程」
按钮）更严重：图层和布局是手搭的，**连 `element_css` 都没有** —— 生成出来的
记录没有 css 块，固件既没有几何也没有样式。新建的工程直接就是整屏不显示。

`CompoentControls::appendChild()`（控件库拖出来的控件）那条路是好的，它
2026-09 就踩过同一个坑，结论写在注释里：**必须从 control.json 模板整份克隆，
不能手搭空壳**。

### 三处一起改

1. `onCreateNewScenesScreen()`：建页时把那条**裸 rect** 属性补上
   （只有 `rect` 键、不带 `-name` —— `rectOf()` 的兜底分支写死了
   `!o.contains("-name")`，带了就读不到）。
2. `createDefault()`：图层/布局改成从 control.json 模板克隆；页的 rect 也
   从带 `-name` 改成裸对象。
3. `ProjectModel` 读工程时，页面没有 rect 就地补一条（治已经存坏的工程，
   只在内存里补、不主动置脏，下次保存自然写回）。
4. `StyBuilder` 取不到父矩形时**不再静默留 0**，退到页面尺寸并往
   `warnings` 里记一条。静默的 0 正是把一个存盘 bug 变成"整屏黑、
   哪儿都不报错"的原因。

### 守卫

ops-test 新增 18o：建工程 → 存盘 → 真的跑一遍 `StyBuilder` → 回头读 `.sty`
里每条记录的 css，**没有 css 块**或**宽高全 0**都算失败，另外还断言生成过程
没有"取不到父级尺寸"的警告。这一条当场就把 `createDefault` 那处抓出来了
（3 条记录里 2 条没有 css 块）。

用户那份坏掉的工程用新版重新导出，页 3 已经是 `宽=10000 高=10000`，
`verify_selfconsistent` 24/24 通过。

## 13. 编辑器一动就散架：选中被 rebuild() 吃掉

**现象**（用户实测三例，同一个根因）：

1. 改一个图片参数、按回车 —— 中间画布当场变成"这一页所有布局叠在一起"；
2. 往当前布局里拖/建一个新控件 —— 同上，而且刚建的那个反而看不见；
3. 很多控件的参数输入框敲回车 —— 同上。

**根因**。`ScenesScreen::applyVisibility()` 的"选中即隔离"是靠 `m_selected`
找那个顶层布局的（父节点是图层的那一层），同级的其它顶层布局整棵不画。
一个图层下常挂着好几个**全屏尺寸**的互斥布局（原厂 SmallColorTFT 页 0 有
5 个 `(0,0,128,64)`），隔离一失效就全画出来，叠成一团。

而 `rebuild()` 开头有一句 `m_selected = nullptr` —— 它本身是对的，重建时那些
BaseForm 全销毁重建，裸指针留着就是野的。问题在于**谁在叫 rebuild()**：

| 触发点 | 动结构了吗 |
| --- | --- |
| `PropertyTab::nodeEdited` -> `MainWindow` 里那条 lambda | 没有 |
| `CompoentControls::appendChild`（拖/点建控件） | 加了一个叶子 |
| `ScenesScreen::setZoom` | 没有 |
| `CanvasManager::reloadMonoColors`（改预览配色） | 没有 |
| `BaseForm::structureChanged`（删/粘/挪层） | 动了 |

只有最后一行真动了结构，前四行**模型的树形状一个字节没变**，却一样被清掉
选中。等于编辑器每动一下就散一次架。

`setZoom()` 早先单独打过一个补丁（记下 `m_selected`、`rebuild()` 完再
`selectNode()` 选回来），但那是一个点上的补丁，另外三条路没覆盖到。

**改法**：把"保住选中"下沉到 `rebuild()` 自己身上，`setZoom()` 的那份实现删掉。

```cpp
UiNode *const keep = m_selected;
m_selected = nullptr;
...  // 旧控件摘干净、照活模型重建
if (keep && m_forms.contains(keep)) {
    m_selected = keep;
    for (auto it = m_forms.constBegin(); it != m_forms.constEnd(); ++it) {
        it.value()->setSelected(it.key() == keep);
    }
}
applyVisibility();
```

两个要点：

* **安全性由 `m_forms` 兜着**。这张表刚刚照活模型走了一遍 `buildRecursive()`，
  `keep` 还在里面就说明这个节点还挂在树上。删节点那条路进来时调用方已经把
  `m_selected` 清了（`BaseForm::structureChanged` 的 lambda 第一句），`keep`
  是空的，不恢复。`keep` 全程只做**键比较、不解引用**，哪怕已经是野指针也
  不会踩内存。
* **不发 `nodeSelected`**。这只是把重建前的状态摆回去，不是用户又选了一次。
  发出去会让 `MainWindow::onNodeSelected` 把属性面板整个重建 —— 而"改属性"
  恰恰是最常见的触发点，输入框会在打字的当口被换掉。

顺带两处：

* `TreeDock::reload()` 里 `m_tree->clear()` 也会把树上的高亮一起清掉，同样
  是"改个参数选中就自己跑了"。先记住当前节点，重建完 `selectNode()` 找回来
  （节点已经不在树上就是空操作）。`TreeDock` 只连了 `itemPressed`，
  `setCurrentItem()` 不会触发任何槽，没有递归风险。
* `CompoentControls::appendChild()` 建完就 `selectNode(新节点)` —— 原厂也是
  这个行为，而且这里还兼着一件正事：什么都没选的时候往布局里拖控件，隔离
  没有目标，这一页的布局会全画出来，刚拖进去的那个反而被盖住。
  顺序是 `rebuild()` -> `emit nodeCreated` -> `selectNode()`：`nodeCreated`
  那条信号会重载控件树，得等树上有了这一项，`selectNode` 才点得亮它。

**ops-test 18p** 把四条路各测一遍：单纯 `rebuild()`、"改属性"那条路
（`rebuild()` + `m_tree->reload()`）、改倍率、新建控件。每条都断言
①选中还在 ②画布上那个控件还是选中态 ③**同级布局露出来的控件数没变**
（隔离没塌）。TFT 176 项 / oled 164 项全过。

## 14. 谁能挂到谁下面：容器规则（从 exe 反出来的）

**现象**：用户问"为什么我的垂直列表下面不能放其他控件？"。本版
`EditorOps::acceptsChild()` 写的是 `return isLayout(n);` —— 只有布局收孩子，
于是列表怎么都装不进东西，永远是空的。

### 14.1 原厂工程里实际存在的父子关系

两个工程（SmallColorTFT + SmallColor_oled）277 个节点全量统计：

| 父 | 键 | 子 | 个数 |
| --- | --- | --- | --- |
| ScenesScreen | `layer` | NewLayer | 15 |
| NewLayer | `layout` | NewLayout | 64 |
| NewLayout | `layout` | NewFrame（Text/ImageList/Time/number/Battery） | 494 |
| NewLayout | `layout` | NewLayout（套娃） | 3 |
| NewLayout | `layout` | NewList（VerticalList / HorizontalList） | 37 |
| **NewList** | **`listwidget`** | **NewLayout** | **165** |

最后一行就是答案：**列表下面挂的是布局** —— 一个布局就是列表的一行/一项模板，
控件再放进这些行布局里。所以"列表能不能放东西"根本不是个选择题，
原厂工程里有 165 处。

### 14.2 点按钮建东西的规则

反的是 `CompoentControls` 的 moc 派发表（`qt_static_metacall` @0x458550，
槽 0..3 分别跳 0x4212C0 / 0x421000 / 0x421500 / 0x421780）。判定用的是一个
虚函数 `vtbl[+4](const char *className)`，返回非 0 表示"是这个类"。

**`onCreateCompoentToCanvas` @0x4212C0（新建控件）**

```
sel = g_selected            // 全局 0x170E784，selectNode 里写的
if (!sel)                        -> 提示 "请选择一个布局或者新建一个并选中它."
if (sel is NewLayer)             -> 同上提示
if (sel is NewFrame/NewList/NewGrid) -> 容器 = sel->[+0x34]   // 父级，当兄弟
else                             -> 容器 = sel                // 布局，钻进去
容器->appendChild(模板json, 1)                                 // 0x41D4A0
```

**`onCreateNewLayout` @0x421500（新建布局）**

```
if (!sel)                  -> 提示 "请选择一个图层或者新建一个图层,并选中它."
if (sel is NewLayout)      -> 容器 = sel        // 布局套布局，工程里 3 例
if (sel is NewLayer)       -> 容器 = sel        // 走 0x41E1F0 那个专用入口
if (sel is NewFrame/NewList) -> 容器 = sel->[+0x34]
else                       -> 什么也不做，连提示都没有
```

两处的"挂到父级"是本版原来没有的：**原厂选中一个文字控件再点「新建文字」，
是在同一个布局里再加一个**，不是弹错误框。本版原来一律拦下，比原厂严。

### 14.3 拖放的规则

拖放走的是画布的 `dropEvent` @0x434D20。它读 mime 里的种类码，然后：

```
esi = g_selected
eax = [esi+0x90]          // option.ini [Control] 里的类型码
if (eax == 0) -> 特殊分支
if (eax == 1) -> 特殊分支（工程/window）
否则           -> 直接 appendChild 到 g_selected      // @0x435419 / 0x4363AF
```

也就是说**拖放几乎不设限**：除了类型码 0 和 1，选中什么就往什么里面塞。
类型码 5 是 `NewGrid`/`VerticalList`/`HorizontalList`，落在"否则"这一支 ——
原厂工程里那 165 个行布局就是这么建出来的（先在树上选中列表，再把「布局」
拖到画布上）。

注意原厂的落点是**当前选中的节点**，不是鼠标松手的位置。本版仍然按落点算
（`ScenesScreen::dropTargetFor`），这一条没有跟原厂改 —— 按落点更符合手册里
"拖动到图层上 / 拖动到布局上"的说法，也更好用；能落的容器集合改成和原厂一致。

### 14.4 本版改了什么

* `EditorOps::isContainer()` 新增：**布局 / 列表 / 表格**三种收孩子。
  `acceptsChild()` 保留原义（只有布局收粘贴）—— 原厂那三条粘贴提示语写死了
  "请选择一个<布局>对像"。
* `EditorOps::hostForNewControl()` / `hostForNewLayout()`：把 14.2 那两棵
  判定树照抄下来，`CompoentControls::createControl()` 和 `onCreateNewLayout()`
  改成调它们。
* `ScenesScreen::dropTargetFor()`：布局能落在 图层/布局/列表/表格 上，
  普通控件能落在 布局/列表/表格 上。
* `EditorOps::childKeyFor()`：`NewGrid` 补 `GridWidget` 键。工程里没有表格
  样本，这个键名是从 ui-tools.exe 的键名池里取的 —— 它和
  `listwidget`/`layout`/`layer` 挨在一起做静态初始化（@0x105DE5F，
  全局槽 0x170E454）。

ops-test 新增 18q（列表是容器：子键、落点规则、真的建一行、行里再放控件、
选中列表建控件要落到父级），并把第 1、3 条按 14.2 改了 —— 那两条原来断言的是
本版自己发明的"一律拦下"。TFT **187 项** / oled **175 项** 全过。

> 顺带记一笔：这些工程里的列表常常被父布局裁得**在画布上一个像素都点不到**
> （比如父布局摆在 x=112，列表却是 128 宽），只能从左边的对象树里选。
> 那是 Qt 的父子裁剪，原厂同样如此，不是本版的毛病。

### 14.5 ★ 有意偏离原厂的一条：选中列表点「新建布局」

用户要求："选中垂直列表点新建布局，布局要落到列表下面"，并且"打开的 json
工程和生成的 UI 资源要保持兼容"。

原厂在这里给的是 `sel->[+0x34]`，也就是布局落到列表**旁边**（`+0x34` 是父指针，
已坐实：`0x0041CA9B  mov [ebx+0x34], edx` 和 `0x0041D6A3  mov [edi+0x34], esi`
—— 两处都是 new 完就把创建时的容器写进去）。原厂想给列表加行只能走列表自己的
右键菜单「添加行」（字符串 @0xC94FD2，槽 `onAddManyLine()`，引用点
0x4168EB / 0x418D06）。

本版改成**加进列表**。`EditorOps::hostForNewLayout()` 里 `isList(sel)` 那一支
从 `return sel->parent` 改成 `return sel`。

**兼容性怎么保住的**：加进去的东西和原厂那 165 个行**同一个形状** ——
`-class` 是 `NewLayout`，挂在 `listwidget` 键下，带完整的 element_css。
ops-test 18q 把这条链走完整：建行 → 存盘 → 重新打开 → 跑 StyBuilder：

* 重新打开后，全工程每一个列表的孩子**全在 `listwidget` 键下**、**全是 NewLayout**；
* 生成资源不报错，且没有"取不到父级尺寸"的警告（零尺寸 = 屏上不显示，见 §12）。

### 14.6 顺带补掉的一个洞：页面 rect 的修复写不出去

§12 给"页面缺 rect"加了个读工程时就地补齐，当时写的是"只在内存里补，不置脏"。
错了 —— `ProjectModel::nodeToJson()` 的整个 property 段是 `if (n->m_dirty)`
门控的，不置脏就直接吐原始 `m_raw`，补的那一条根本写不出去。而生成资源那条链
读的是**存盘后的 json**，不是内存模型，于是"界面上看着好了、烧进去还是黑屏"。

改成补完 `n->markDirty()`。注意**不能**顺手把那条 property 也置脏：置脏会让
`nodeToJson()` 往里塞 `-name`/`-type`，而页节点这一条必须是**裸对象**
（只有 `rect` 键，见 §12）。坐标由 `po.contains("rect") && p.name.isEmpty()`
那一支照 `n->rect` 刷。

这个洞是 18q 的"存盘→重开→生成"那三条断言当场撞出来的 —— 用户工程
`ui_128_64_JL02_rebuilt` 的页 3 至今 `"property": []` 都没有，
之前那版打开时补了、存下去还是没有。

### 14.7 谁能装什么（本版最终规则）

| | 装「布局」 | 装「普通控件」 | 收粘贴 |
| --- | --- | --- | --- |
| 图层 NewLayer | ✔ | ✘ | ✘ |
| 布局 NewLayout | ✔（套娃） | ✔ | ✔ |
| 列表 NewList | ✔（就是行） | ✘ | ✘ |
| 表格 NewGrid | ✘ | ✘ | ✘ |
| 控件 NewFrame | ✘ | ✘ | ✘ |

`EditorOps::acceptsLayout()` / `acceptsWidget()` / `acceptsChild()` 三个谓词。

* **列表装不下裸控件**：原厂两个工程里列表的孩子清一色 `NewLayout`，
  一个 `NewFrame` 都没有。塞裸控件进去生成出来是原厂从没产出过的形状，
  固件按"行"遍历也拿不到它。拖控件落在列表上时，落点会一路上溯到列表的父布局。
* **表格不放开**：两个工程都没有样本，它自己有「添加行/添加列」。
* **收粘贴仍然只有布局**：原厂那三条提示语写死了"请选择一个<布局>对像"。

ops-test：TFT **197 项** / oled **185 项** 全过；dialog-smoke 16/16；
`verify_toolchain` 不合格 0 项。

### 14.8 水平列表 / 表格：和垂直列表同一套

水平列表根本不用单独处理 —— 它的 `-class` 就是 `NewList`（`-type` 才是
`HorizontalList`），`isList()` 天然覆盖。扩展控件 slider / vslider 同理，
它们的 `-class` 是 `NewLayout`，本来就按布局收孩子（原厂 `MUSIC_FILE_SLIDER`
底下挂着三张图片）。

表格 `NewGrid` 是另一个类，本版把它和列表同等对待，依据三条：

* `option.ini` 里 `NewGrid` / `VerticalList` / `HorizontalList` **同为类型码 5**，
  `StyBuilder` 走的是同一条路；
* 固件 `ui_grid.h` 的 `struct ui_grid_item_info` 里每一项就是
  `struct layout_info *info` —— 和列表的行是同一种东西；
* `StyBuilder` 遍历子节点用的是固定键表
  `{ "layer", "layout", "widget", "listwidget" }`（StyBuilder.cpp:411），
  表格的项挂 `listwidget` 才走得进去。

### 14.9 「往列表里放了张图，预览什么都看不到」

用户实测：水平列表里建一个布局，布局下面放一张图片，预览里看不到内容。
查下来是两个毛病叠一起，都和"格子"有关。

**毛病一：新建的行不是格子的尺寸。** 原厂工程里行的 rect 就是那一格：

| | 列表 rect | sizehw | 行 rect |
| --- | --- | --- | --- |
| VerticalList | (0,16,128,32) | 16 | (0, i*16, **128**, **16**) |
| HorizontalList | (0,24,128,40) | 32 | (i*32, 0, **32**, **40**) |

也就是 **垂直：宽=列表宽、高=sizehw；水平：宽=sizehw、高=列表高**，
位置按第几格递推（`sizehw + space` 一步）。新建的行却拿的是 control.json
的通用默认值（布局 100x100），比格子大三倍，容器一裁就只剩一条边。
现在由 `EditorOps::cellRectFor()` 统一算，`appendChild()` 建到列表/表格里时
直接用它，而且**不跟鼠标落点走** —— 格子里的项，位置由第几格决定。

**毛病二：`NewList::relayoutRows()` 只在滚轮翻行时跑过。** 它是唯一把各行
摆到格子上的地方，却只被 `setFirstVisible()` 调 —— 画布重建之后一次都没跑，
行是散的。加了两个调用点：

* `BaseForm::onSubtreeBuilt()`（新虚函数），`ScenesScreen::buildRecursive()`
  在**孩子全建完之后**调一次 —— `bind()` 那会儿一个孩子都还没有，在那儿
  relayout 是空转；
* `NewList::resizeEvent()` —— 列表一改大小，水平列表的行高就跟着变。

**顺带：新控件的默认尺寸夹到父容器。** control.json 的模板默认值是给大屏留的
（图片 75x75、布局 100x100、文字 75x25），128x64 的屏上本来就偏大，放进
一格才 30x25 的行里更是整个溢出 —— 图片被裁在格子外面，一个像素都露不出来。
现在建的时候把宽高夹到父容器尺寸。这不是新规矩：属性面板上宽/高的取值范围
本来就是 `0..父容器宽/高`（原厂 `setMaximum`，见 §10），75x75 这种值
**原厂的属性面板自己都不让你填进去**。只夹尺寸不动位置 —— 位置是用户松手的
地方，挪走等于不听话（ops-test 第 14 条盯着这件事）。

ops-test 18s 把用户那条路整个走一遍：水平列表 → 行布局 → 图片 → 选一张真图,
然后两头各查一遍：

* **预览**：抓**列表这一层**的画面数点亮像素（抓图片控件自己没用 —— Qt 会把它
  裁在行里、行又裁在列表里，控件自己那张图是完整的，用户看到的却可能只剩一条边）。
  修之前 4 个点亮像素，修之后 **625** 个。
* **资源**：这张图有没有进 `Resbuilder.xml`（那就是交给 ResBuilder 的清单）。
  进了 —— 所以"会不会导出到资源"这一半，答案是**会**，之前也一直会，
  看不见纯粹是画布裁剪的问题。

TFT **236 项** / oled **224 项** 全过；dialog-smoke 16/16；
`verify_toolchain` 不合格 0 项。

### 14.10 行高 / 间隔改完预览不动；加的行叫英文名

用户实测两条，都在列表右键菜单那一片。

**（一）改完不生效。** `onSetFixedHeight()`、「设置间隔」、「垂直/水平滚动」、
表格的「添加行/添加列/单元尺寸/单元间距/设置行列」，原来清一色是
`setExtra(...) + update()` —— 三件事一件没做：

* 没重排各行（`relayoutRows()` 当时只有滚轮翻行才会跑，见 §14.9）；
* **没更新各行节点的 rect** —— 行的矩形就是那一格，`sizehw` 变了它就该变；
* 没往上发信号，右栏预览不知道，工程也不算改过。

现在统一走 `BaseForm::cellParamsChanged()`：`reflowCells()` 按
`EditorOps::cellRectFor()` 把每个孩子的矩形重算一遍，再 `emit structureChanged()`
（画布整个重建，重建里 `onSubtreeBuilt()` 把行摆好；树、页面栏跟着刷；
CanvasManager 顺手置脏）。右键菜单问完数字之后调的是新开出来的
`NewList::setCellSize/setCellSpace/setOrientation`、
`NewGrid::setCellSize/setCellSpace/setGrid` —— ops-test 也直接调它们，
免得为了测一条规则去驱动模态对话框。

**（二）加的行叫 `NewLayout`。** `onAddManyLine()` 的退化分支（列表里还没有
行可克隆时）现搭了个 `-name: "NewLayout"`；克隆分支则沿用被克隆那一行的名字。
原厂的名字是**中文 caption 加全局序号**（图层_0 / 布局_1 / 文字_48，序号跨页
连着走）。抽了个 `EditorOps::defaultNodeName(caption)` 出来，两条建节点的路
共用，加出来的行现在叫 `布局_314`，caption/icon 也补齐。

### 14.11 「间距参数到底有没有进资源」

**没有 —— 而且原厂也没有。** 类型码 5（列表/表格）在资源里的结构体是：

```c
struct ui_grid_info {              /* User/ui_framework/include/ui/control.h:170 */
    struct ui_ctrl_info_head head; /* +0  16 字节 */
    u8  page_mode;                 /* +16 */
    s8  highlight_index;           /* +17 */
    struct element_event_action *action;  /* +20 */
    struct layout_info *info;             /* +24 */
};
```

`StyBuilder` 写的正是这四样（`rec[16]=scroll_mode/page_mode`、
`rec[17]=highlight_index`、+18/19 是对齐空洞填 0xFF、@20 action、@24 子指针），
和原厂逐字节一致。**里面没有 `sizehw`，也没有 `space`。**
（`ui_grid.h` 里那个 `u16 interval` 是**运行时**结构 `ui_grid_item_info` 的字段，
不是资源结构；`control.h` 里另外两个 `interval` 属于 `ui_browser_info` 和
`ui_animation_info`，都不是列表。）

那行距在设备上靠什么？**靠每一行自己的 rect。** 原厂工程里对得上：

| | 列表 rect | sizehw | space | 各行 rect |
| --- | --- | --- | --- | --- |
| VerticalList | (0,16,128,32) | 16 | 0 | (0, i*16, 128, 16) |
| HorizontalList | (0,24,128,40) | 32 | 0 | (i*32, 0, 32, 40) |

行按 `sizehw + space` 一格一格排开，`sizehw`/`space` 只是编辑器算格子用的中间量,
算完就落在行的矩形上，json 里留着它们是给编辑器下次打开接着算。

**所以这个 bug 比"预览不刷新"严重**：改完不重排行 = 这个参数对生成的资源
**一点影响都没有**。ops-test 18t 直接拿字节证明现在生效了 —— 改 space 前后
各跑一遍 `StyBuilder`，比较 `.sty`：

```
[通过] 改间隔真的改到资源里了（.sty 字节变了）  —— 改前 17180 字节 / 改后 17180 字节 / 有差异
[通过] 而且生成两遍是稳定的（同样的模型出同样的字节）
```

长度不变、内容有差异 —— 正是"只有各行 css 里的几何变了"该有的样子。
同时 `verify_toolchain` 对原厂参考仍然**不合格 0 项**，说明没有往记录里
多写任何原厂没有的字节。

ops-test：TFT **248 项** / oled **236 项** 全过；dialog-smoke 16/16。

## 15. 全量对拍：不再一个一个补

用户的原话："你能不能全面的和原厂的对比一遍，你做的不是漏这个，就是漏哪个。"
说得对 —— 前面几轮都是"报一个修一个"。这一节把不变量一次性立起来，
从原厂那两份工程（**797 个节点**）和 `control.json` 统计出来，编成
ops-test **18v**，每种控件 × 每条建节点的路全跑一遍。

### 15.1 不变量是怎么来的

拿 797 个原厂节点逐个对 `control.json` 的模板，偏差只有三类、共 32 个：

| 偏差 | 个数 | 结论 |
| --- | --- | --- |
| `number` 在模板里找不到 | 15 | **是本版的 bug**，见 15.2 |
| `ImageList` 只有 `id`+`element_css` | 9 | 原厂自己的历史数据，**软性** |
| `Time` 的 css 状态数和模板不同 | 8 | 用户自己加的状态，**软性** |

除此之外 765 个节点和模板**完全一致**。所以：

* **硬性**（违反了就是坏数据，生成出来烧进去要出事）
  * 认得出类型（`control.json` 里有模板）
  * 有 `element_css` —— 没有就是零尺寸，整屏不显示（§12）
  * 有 `id` 属性且 `ename` 非空 —— 空的写出 `#define  0X...`，编译器当场炸
  * `ename` 全工程唯一
  * `rect` 有效且宽高 > 0
  * 子键 ∈ `{layer, layout, widget, listwidget}`
  * 父子组合 ∈ 原厂出现过的那几种（§14.1 那张表）
* **软性**（原厂自己就有 2%，只报数）：属性名单、css 形状与模板不一致

**新建**出来的节点按"硬性 + 严格照模板"要求；**已有工程**只查硬性。

### 15.2 对拍当场逮到的三个漏

**（一）`ControlLibrary::byType()` 大小写敏感。** `control.json` 里数字控件是
`-type: "Number"`，而工程文件和 `option.ini` 里都是小写 `number`
（两个工程 15 个数字控件全是小写）。按大小写敏感查，这 15 个节点**取不到模板**
—— 补样式、补 ID 号全部落空，而且不报错。改成
`compare(..., Qt::CaseInsensitive)`。（`StyBuilder` 早就绕过这一点了：认不出
`-type` 就退回按中文 caption 查 `option.ini` 里的 `数字=15`。）

**（二）新建工程的图层/布局没有唯一 ID 号。** `ProjectModel::createDefault()`
从模板克隆，但没像 `CompoentControls::appendChild()` 那样补 ename。空 ename
既让业务代码引用不到这个控件，又会让 `ename.h` 写出 `#define  0XC30002`。

**（三）空壳节点连 `id` 属性都没有。** 旧版「添加行」现搭的壳
（§14.12）没有 `id`，`ename` 自然是空的 —— 用户报的
`#define  0XC30002` 就是这么来的。三道一起堵：

* 建节点那条路：`EditorOps::makeFromTemplate()` 统一从模板建 + 分配 ename，
  「添加行」的退化分支改走它；
* 存量数据：`CanvasManager::healBrokenNodes()` 打开工程时补齐缺 `element_css`
  和缺 ename 的节点（补完置脏，用户保存就落盘），状态栏报"修复了 N 个"；
* 生成器兜底：`StyBuilder` 遇到空宏名**不再写进 `ename.h`**，改成一条警告
  点名是哪个控件 —— 宁可少一个宏，也不能吐出编译不过的头文件。

### 15.3 18v 跑了些什么

1. 打开进来的工程整棵扫一遍（硬性 0，软性只报数）
2. 每种控件从**控件栏**建一个 → 严格照模板
3. 每种控件**拖**一个进去 → 严格照模板
4. 垂直列表 / 水平列表 / 表格，各走四条路：
   空容器加第一项、再加第二项（列表走克隆）、选中容器点「新建布局」、
   项里再放一个图片 → 每个都严格照模板
5. 图层下建布局
6. 折腾完整棵再扫一遍
7. 存盘 → 重开 → `StyBuilder`：
   `ename.h` 每条 `#define` 都得有宏名、没有"取不到父级尺寸"、
   没有"没有唯一ID号"

TFT **397 项** / oled **385 项** 全过。

`verify_toolchain.py` 跑一次，ResBuilder 的产物就**就地**落回工程目录

现在脚本跑之前把参考产物拍进内存，**比对用快照**，跑完原样写回去

`project.bin` 是 `.gitignore` 掉的，恢复不了，按 §9 的方法用**原厂

## 16. 属性面板也要全量对拍

§15 那轮"全量对拍"只比到**数据结构**：属性名单、element_css 字段、状态数。

### 16.1 两条的根因

**「事件属性」没了：`healBrokenNodes()` 补得不全。** 那个行布局是旧版

## 17. 属性面板拆成两页（本版有意偏离原厂）

### 17.1 为什么拆

原厂属性区是**上下堆叠**三块：ID号 / `CSS属性_0`、`_1`… 页签 / 控件专有属性区。
一个「文字」控件铺满 22 行，「时间」「数字」更长，窄边栏里必须滚动才看得全。

用户要求拆成两个页签：一页参数，一页资源。

### 17.2 分法（以及为什么边框跟着背景走）

先算了一遍账：纯按"参数 vs 资源"分，**基础页反而更高**——

| | 内容 | 行数 |
| --- | --- | --- |
| 资源页 | 背景颜色、背景图片、文字列表 | 3~4 |
| 基础页 | 对齐/隐藏/标志、**坐标(4行)**、**边框(5行)**、数据源、编码格式、文字颜色、高亮颜色、事件属性 | **17** |

高度大头是 `坐标`(4 行) 和 `边框`(5 行) 两个组框。所以把 **`边框` 也归资源页** ——
它和背景一样是外观装饰，不是控件行为参数。这样才真正降下来：

| 控件 | 基础设置 | 资源 |
| --- | --- | --- |
| 文字 | 10 行 | 4 行 |
| 图片 | 11 行 | 4 行 |
| 时间（最长） | **13 行** | 4 行 |

最终归属：

| 页 | CSS 属性页的字段 | 专有属性 |
| --- | --- | --- |
| **基础设置** | `align` `invisible` `flags`(图层是 `z_order`) `rect` | 数据源、编码格式、预览文字、格式、自动记时、滚动方式、默认高亮…、旋转中心点 X/Y、颜色类型、文字颜色、高亮颜色、事件属性 |
| **资源** | `background_color` `background_image` `border` | 各种图片列表、文字列表 |

两条判定规则都**数据驱动**，不是手维护的名字清单：

* CSS 字段按 `-name` 判（`background_color` / `background_image` / `border` → 资源）；
* 专有属性按 `-type` 判（`piclist` / `arrlist` / `text-pic` → 资源，其余留基础）。
  加新控件类型不用回来改清单。

**「预览文字」没有挪到资源页**（和先前给用户的方案不同，这里改了主意）：
它的显示/隐藏由「编码格式」那个下拉框实时控制（`syncPresetRow`），
拆到两页去，用户会看到"在这一页点了个下拉框，另一页凭空多出/少掉一行"。

### 17.3 CSS 状态从页签降级成下拉框

原厂用页签切 CSS 状态（`CSS属性_0` / `_1`）。背景和边框挪到资源页之后，
**两页都受状态影响**，状态选择器不能再藏在其中一页里 —— 提到 ID号 下面常驻。

原厂挂在页签右键上的四个动作（清除 / 复制添加 / 复制插入 / 删除活动项）
跟着挪到**状态下拉框的右键**上，动作和原厂一字不差。

### 17.4 其余行为

* **ID号 常驻**在页签之上 —— 它是控件的身份，切页签不该看不见；
* **换一个控件回到第一页、第一个状态**（用户明确要求）。不同控件的参数完全
  不一样，停在上一个控件的第二页上，会让人以为"这个控件没有基础参数"。

### 17.5 踩的坑

`ComProperty::showNode()` 那个铺行的循环里有十几处 `m_dynForm->addRow(...)`
和 `new X(m_dyn)`，要按分区分流。第一版图省事，在循环体里声明了两个**同名**
局部量去遮蔽成员：

```cpp
QFormLayout *const m_dynForm = isRes ? m_dynFormRes : this->m_dynForm;  // ✗
```

两个问题：循环里有 lambda（`syncPresetRow`）会捕获它，无默认捕获模式下
**捕不到局部量**，编译不过；而且机械改名时右边那个 `m_dyn` 也被一起换掉，
变成 `QWidget *const dynHost = isRes ? m_dynRes : dynHost;` —— **自己初始化
自己**，拿到的是垃圾指针，`--ops-test` 跑到第 3 条就 0xC0000005。

老实换名成 `dynForm` / `dynHost`，lambda 按值捕获 `dynForm`，问题消失。
（这个崩溃是靠给 `check()` 加一条"逐条落盘的脚印"定位的 —— 崩在写报告之前，
报告根本回不来，读到的都是上一次的旧文件，白白误判了两轮。）

### 17.8 补：拆页签把「新建 CSS 属性」弄丢了

用户反馈"现在不能新建 css 属性了吗？原来是有的"。

原厂那四个动作（清除 / 复制添加 / 复制插入 / 删除活动项）挂在 **CSS 状态页签**
的右键上，页签永远点得到。本版把状态换成下拉框之后，我顺手写了一句：

```cpp
m_stateCb->setEnabled(n != nullptr && want > 1);   // ✗
```

**禁用的控件收不到 contextMenuEvent** —— 只有一个 CSS 状态时下拉框是灰的，
整套菜单就点不出来了。而"只有一个状态、想加第二个"恰恰是最常见的场景。

改法：
* 只要选中了控件，下拉框就可用（只有一条也无所谓）；
* 右键挂到**整行**（标签 + 下拉框 + 空白处都算），菜单弹出坐标按 `sender()` 换算。

**为什么原来的测试没拦住**：它调的是 `m_prop->onCopyAppendState()`，
直接调槽，绕过了界面 —— 界面坏了它照样绿。新增 18y 盯"够不够得着"：
`stateMenuReachableForTest()` 检查下拉框 `isEnabled()` **且**行和下拉框的
`contextMenuPolicy` 都是 `CustomContextMenu`，再走一遍复制添加/删除活动项。
