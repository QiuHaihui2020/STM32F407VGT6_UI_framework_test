# tool —— UI 工具目录

点阵屏 UI 工具链。**一个 exe，不依赖任何 dll。**

本目录住在它服务的那个 UI 工程里 —— `<UI工程>\tool\` —— 所以工程那边用
`..\tool` 就找到这里，没有任何地方写死工具目录叫什么名字。固件那边一行都不用改。

源码在 [`../tool_src/`](../tool_src/)。本目录由 `tool_src\mkdist_tooldir.bat`
生成，**不要手改** —— 改了下次重新生成就没了。

---

## 目录里有什么

```
UITools.exe    编辑器 + --gen + --pack，14 MB，静态链接
template\      新建工程用的空工程（上一级的 新建工程.bat 克隆它）
自检.bat        对 ..\project 跑 25 项自洽性检查（要 python3 和源码树）
README.md      本文件
```

就这四样。以前这儿还有两个 exe、三个 Qt dll、三个插件目录、`assets\`、
`compat\`、`clear.bat`/`clear.sh`，一共十六项。

### 一个 exe，三个入口

| 命令 | 干什么 |
|---|---|
| `UITools.exe` | 布局编辑器 |
| `UITools.exe --gen` | 工程文件 → `project.bin` + `ename.h` + `Resbuilder.xml` + `debug.txt` |
| `UITools.exe --pack` | `Resbuilder.xml` + 图片 + xls → `result.bin` / `result.str` + 5 个头文件 |
| `UITools.exe --clean [目录]` | 删掉生成物（逐个文件名，不用通配符） |

子命令在 `src/main.cpp` 的 `dispatchSubcommand()` 里分发。以前这是三个可执行
文件，合成一个之后目录少两项，静态链接时 Qt 也只打包一份 —— 三个各链一份的话
体积要翻两倍多。

### 数据放在哪

**只读的编进 exe 了**（`resources/assets.qrc`）：控件库、控件类型码表、内置的
两个扩展控件（slider / vslider）。判据只有一条 —— **UI 工作过程中会不会被写**；
会被写的一律留在磁盘上，因为编进 exe 就改不了了。

留在磁盘上的：

| 位置 | 干什么 | 什么时候出现 |
|---|---|---|
| `..\project\*.xls` | 多国语言表。**要改文案**；而且它的路径要写进工程的 `Resbuilder.xml`，由打包那一步按路径打开（那是另起的一个进程，塞 `:/` 路径没用） | 跟着工程走 |
| `assets\widgets.d\` | 你「保存成控件」存的 | 第一次存的时候自动建 |
| `assets\canvas\` | 画布背景图（JPG） | 「修改背景图片」里点「打开图片目录」 |

磁盘上有同名文件就**盖掉**内置那份 —— 想改内置控件库，把它拷出来放到
`assets\widgets.json` 改就行，不用重编。解析顺序见
[`../tool_src/src/core/AssetPaths.h`](../tool_src/src/core/AssetPaths.h)。

不产缓存和中间文件：`Resbuilder.dat`（每次全量算）、`uitoolbin.bin`（不需要）。

## 日常用法

### 打开工程

工程就在上一级 [`../`](../)。三种方式，随便哪种：

1. **双击 `tool\UITools.exe`** —— 不给任何参数，它自己往 `..\project` 找
   `config\ini\project.ini`，把里面 `projectfilename` 指的那份打开。
2. **双击工程文件 `..\project\*.uiproj`** —— 先跑一次上一级的
   `注册文件关联.bat`（只写当前用户的注册表，不需要管理员；只碰 `.uiproj`，
   不动 `.json` —— 关联 `.json` 会抢走系统里所有 json 文件的双击）。
3. **拖进编辑器窗口** —— 工程文件、`project\`、或者整个 UI 工程目录都认。

### 生成资源

工具栏上点「资源导出」（快捷键 F5）。**它点了直接跑，不弹界面** —— 跑的是完整
那条链（`--gen` → `--pack` → `copy_file.bat`），进度和输出打在状态栏。

要改工程ID / 调用脚本 / 旋转 / 功能设置，在主窗口空白处**右键 →
「资源导出设置…」**，那一页上也有「生成资源文件(F5)」和「清理生成物」两个按钮。
那一页各行就是 `project\config\ini\project.ini` 里的内容，点生成时写回去：

```ini
[Project]
projectfilename=SmallColorTFT.uiproj  ; 要生成哪个工程
projectid=0                           ; 工程 ID，进控件 id 的 bit29..31
projectrotate=0                       ; 0/1/2/3 -> 0°/90°/180°/270°
projectbatscript=copy_file.bat        ; 收尾脚本
projectresbuilder=false               ; true = 不重新生成资源
```

编辑器保存工程时会把 `projectfilename` 写回这个文件，所以新建工程后不用手填。

不想开界面就走命令行：

```
cd <UI工程>\project
..\tool\UITools.exe --gen --run-resbuilder
```

### 新工程

```
新建工程.bat <工程名>          （在上一级）
    例: 新建工程.bat ui_128_64_MY
```

在 `LCD_UI工程\<工程名>\` 拉出一份完整的空工程 —— 空 `project\`、几个脚本，
外加一份 `tool\`（本目录整份拷过去，约 15 MB）。每个 UI 工程都是自足的一个
目录，删掉就干净了。然后：

1. 把 BMP 放进 `<工程名>\project\config\pic_lcd\`
2. 把多国语言表（`*.xls`）放进 `<工程名>\project\`
3. 双击 `<工程名>\tool\UITools.exe`，用「新建工程」建页面并保存
4. 点工具栏的「资源导出」
5. 按需改 `project\copy_file.bat` 里的两个路径（资源目录 / 头文件目录）

### 界面上能做什么

工具栏（从左到右）：

| 按钮 | 干什么 |
|---|---|
| 新建工程(P) | 建一个空工程 |
| 打开工程(O) | 打开 `.uiproj` / `.json` |
| 保存工程(S) / 另存为(A) | 存盘；另存为默认沿用当前后缀 |
| 新建页面(N) / 删除页面(D) | 加/删一页 |
| **资源导出** | **点了直接跑**完整生成链，不弹界面（快捷键 F5） |
| 截屏(P) | 把程序界面存成 PNG |
| 全局设置 | 五条路径（多国语言文件 / 控件文件 / 图片资源目录 / 工程目录 / 自定义控件目录）+ 点阵屏预览配色 + 界面配色 |
| 工程缩放 | 整页按比例缩放（宽高不成比例会截断、坐标清零） |
| 关于(I) | 版本信息 |

工具栏右侧还有：**预览缩放**（25%–800%）、**显示隐藏项**、**单独预览**
（同级其它画面一个控件都不画）、**隐藏辅助线**（整页只剩亮/灭两种像素，
看到的就是屏上的样子）、**当前画面 n/m** 下拉。

主窗口空白处**右键**：

| 菜单项 | 干什么 |
|---|---|
| 显示隐藏项 / 单独预览 / 隐藏辅助线 | 和工具栏右侧那三个开关是同一套 |
| 解析 .sty 并校验往返 | 挑一个 `.sty` 解开看结构，顺带做往返校验 |
| 画布背景色… | 换画布底色，或从 `assets\canvas\` 里挑一张参考底图 |
| 网格开关 | 像素网格（倍率 ≥300% 才画） |
| **资源导出设置…** | 弹出生成那一页：工程ID / 不重新生成资源 / 调用脚本 / 旋转 / 版本配置 / 功能设置，外加「生成资源文件(F5)」和「清理生成物」 |
| 工程配置… | 工程级设置 |

四栏布局：**对象树**（结点 / 属性 / ID号）、**控件列表 + 属性面板**、
**画布**、**当前页布局 + 页面缩略图**。

三个面板都能拖动、浮动、关掉。

### 编辑操作与限制

逐条对照见 `../tool_src/docs/UI_BEHAVIOR.md` 第 5 节：

* **从控件列表把控件拖到画布上**建控件 —— 这是主要手势。落在哪个容器
  上就挂到哪个容器下，落点就是控件坐标；落到所有布局之外时拒绝（松手前指针
  就是禁止符号）。
* **点击建**是第二条路：要先选中一个布局（建布局则要先选中图层），否则拦下来
  并给出提示。建完弹框问名字，默认名是整页流水号（图层_0 / 布局_1 /
  电池电量_2 …）。
* **CSS 属性页整页都能改**：对齐方式、默认隐藏、标志、背景色、背景图片、
  内边框线、滚动方式……
* **列表能用滚轮翻行**，背景色/背景图右边有清除键。
* **右键菜单画布和对象树是同一套**：删除当前-xxx / 保存成控件 / 显示·隐藏（自己
  和子对象两档）/ 复制 / 粘贴 / 移到顶层·上一层·下一层·底层 / 查找对像。
  列表和表格再各加自己的（添加行列、行高列宽、间隔、滚动方向、单元尺寸）。
  页面空白处右键是：删除当前页面 / 修改背景色 / 修改背景图片。
* **粘贴只有布局收**，不收的时候按两句不同的话分别拒绝。
* **删除一律先问**，按钮就叫 `<删除>`；这个工具没有撤消，所以默认焦点在"取消"。
* **改了没存**就要新建/打开/退出时会拦一道。
* **宽高不能设成 0**，直接拦下来告诉你，而不是偷偷改成 1。
* **对话框**：[全局设置]是五条路径（多国语言文件 / 控件文件 / 图片资源目录 /
  工程目录 / 自定义控件目录）；另有 [工程缩放]、[图片编辑]、[显示列表]、
  [工程设置]、[事件动作]。

## 命令行一览

一个 exe 三个入口。**编辑器的选项直接跟在后面；生成和打包要先写 `--gen` /
`--pack`**，它们从 argv 里被摘掉，后面的参数原样传给对应那一段。

### 编辑器 `UITools.exe`

不给任何参数 = 打开 `..\project` 里的工程（见上文「打开工程」）。

| 选项 | 干什么 |
|---|---|
| `<工程文件>` | 直接打开它（`.uiproj` / `.json` 都认）。双击关联文件走的就是这条 |
| `--tools-root <目录>` | 工具目录。不给就按 exe 旁边 → `..\tool` → 老布局的顺序自己找 |
| `--clean [工程目录]` | 删掉生成物，默认当前目录。逐个文件名删，不用通配符 |
| `--sty-dump <JL.sty>` | 只解析 `.sty` 打印结构 + 往返校验，不开界面 |
| `--json-roundtrip <文件>` | 读进来再写出去，与原文件**逐字节**比。工程文件读写兼容性的硬指标 |
| `--json-rebuild <文件>` | 把**每个节点都标脏**再写出，同样要求逐字节相同。这一项才证明"改过的重建出来也一样" |
| `--out <文件>` | 配合上面两个，把重写结果落盘 |
| `--dialog-smoke [工程目录]` | 15 个对话框各造一遍再销毁，查有没有一开就崩 |
| `--ops-test [--out <报告>] <工程文件>` | 无人值守跑一遍"编辑操作与限制"，逐条打结果（正常 449 项） |
| `--click-test <N> <工程文件>` | 连续选中 N 个节点（走和点对象树完全相同的那条路），复现选中链路上的死循环 |
| `--shot <png>` | 启动后自截主窗口再退出。走 `QWidget::grab()`，**锁屏/无人值守也能出图** |
| `--zoom <倍率>` | 自截前把画布缩放到指定倍率 |
| `--select <N>` | 自截前选中第 N 个节点（看隔离效果） |
| `--no-chrome` | 自截前隐藏辅助线（控件描边/选中框/控件名/像素网格） |
| `--preview-dump <目录>` | 把每个控件的内容预览各存一张 PNG |
| `--make-sample <out.json>` | 造一份"每种控件各一个 + 各种组合"的样例工程 |
| `--sample-pics <目录>` | 配合上面，样例里图片控件到哪儿找图（默认 `config/pic_lcd`） |
| `--export-test` | 走「资源导出」那条路跑一遍再退出（不跑收尾脚本） |
| `-h` / `--version` | 用法 / 版本 |

### 生成 `UITools.exe --gen`

工程文件 → `project.bin`(=JL.sty) + `ename.h` + `Resbuilder.xml` + `debug.txt`。

**不带任何生成类选项时弹界面**；带了就走命令行不弹窗。

| 选项 | 干什么 |
|---|---|
| `<工程文件>` | 不给就读当前目录 `config\ini\project.ini` 的 `projectfilename` |
| `--pj-id N` | 工程 ID，进控件 id 的 bit29..31，默认 0 |
| `--rotate N` | 0/1/2/3 → 0°/90°/180°/270° |
| `--option-ini <路径>` | 控件类型码表。默认用编进 exe 的那份 |
| `--excel <路径>` | 写进 `Resbuilder.xml` 的 `excel_path` |
| `--language 0xNN` | 语言掩码，默认 `0x13` |
| `--ename <ename.h>` | 复用已有 `ename.h` 里的 id —— 和既有资源逐字节比对时用 |
| `-o <目录>` | 输出目录，默认与工程文件同目录 |
| `--verify <目录>` | 生成后与该目录里现成的一套产物逐字节对比 |
| `--run-resbuilder` | 接着跑打包（起本 exe 的 `--pack`）。后面可以跟一个路径，那是老脚本的写法，文件不存在就退回起自己 |
| `--script <bat>` | 最后调用的收尾脚本，默认 `copy_file.bat` |
| `--no-script` | 不跑收尾脚本 —— **不想动固件树就加它** |
| `--gui` / `--cli` | 强制界面 / 强制命令行 |
| `--verify-resxml <工程目录> [--report <文件>]` | 只验「功能设置」：读得进现成的 `Resbuilder.xml`，再写出去还是同一份。不动原文件 |
| `--selftest-generate` | 等于自动点一次「生成资源文件」，跑完退出 |
| `--shot <png>` / `--shot-feature <png>` | 截这一页 / 截「功能设置」对话框 |

命令行显式给的选项**优先于** `project.ini`。所以日常那一行可以很干净：

```
cd project
..\tool\UITools.exe --gen --run-resbuilder
```

### 打包 `UITools.exe --pack`

`Resbuilder.xml` + 图片 + xls → `result.bin`(=JL.res) / `result.str`(=JL.str) /
`result.h` / `res_ver.h` / `result_pic_index.h` / `result_str_index.h` /
`result.csv` / `result.xml`。

| 选项 | 干什么 |
|---|---|
| `<Resbuilder.xml>` | 不给就找当前目录的 `Resbuilder.xml` |
| `-o <目录>` | 输出目录，默认与 xml 同目录 |
| `--verify <目录>` | 生成后与该目录里现成的产物逐字节对比 |
| `-h` | 用法 |

### 退出码

`0` 成功。`--json-roundtrip` / `--json-rebuild` 不是逐字节相同、`--ops-test`
有失败项、`--verify` 有差异，都会返回非零 —— 脚本里判这个就行。

> **`--gen` / `--pack` 的输出**：这个 exe 是 WIN32 子系统的（双击不蹦黑窗口），
> 命令行模式下会把父进程的控制台接回来。但**已经重定向到文件或管道时不接** ——
> 接了会把重定向顶掉，那头收到的是空文件。

工程文件的后缀 `.uiproj` 和 `.json` **两种都认**，内容都是 json；换后缀只是
为了能做文件关联。

## 校验

校验脚本在源码树的 `../tool_src/compat/`，不跟着工具目录发出去 —— 那是开发
资产，而且这些检查要对着固件的头文件做，本来就只在这棵树里才有意义。

```
python ..\tool_src\compat\verify_selfconsistent.py <产物目录> <固件的 include\common 目录>
```

只看产物自身，对着固件的加载路径逐条查：`UI_VERSION` 一致性、三个页表 CRC、
控件 id ↔ ename 宏的双向对应、id 位域自洽、指针落点与重定位表、
资源号范围、`.res`/`.str` 的 head_crc、以及 `ui_style.h` 硬依赖的宏在不在。
25 项，全过才算能上机。上一级的 `自检.bat` 就是跑它。

想和工程目录里现成的那套产物逐字节比对：

```
python ..\tool_src\compat\verify_toolchain.py <bin 目录> <工程目录> <临时输出目录>
```

「双击 exe 能不能自己找到工程」这条也要能验 —— 它失败的样子是起来一个空窗口，
不报错：

```
cd <UI工程>\tool
UITools.exe --ops-test --out r.txt      # 不给工程路径
```

工程没找到的话控件库那一串断言立刻塌下来（正常是 449 项全过）。

其余脚本见 `../tool_src/README.md` 的校验脚本表。

## 两件必须知道的事

**1. id 会变，资源和头文件必须一起换。**
控件 id 是 `CRC16(宏名)` + 线性探测算出来的，**确定性**的，只有增删/改名控件时
才变 —— 但和别处生成的那一套对不上。`copy_file.bat` 本来就是把 `ename.h` 和三个
资源文件一起拷过去的，照常跑没事；但**不要**手工只拷 `JL.sty` 而不更新
`style_jl02.h` —— 那样 id 对不上，界面整个不出来。

**2. 和参考产物的差异都落在不可复现的位置上。**

| 差异 | 原因 |
|---|---|
| `project.bin` 61 字节 | Time/number 控件 `char format[16]` 尾部，参考文件里是没清零的堆内存 |
| `result.bin`/`result.str` 各 4 字节 | 文件头 `resver`，参考文件里是随机值；这里改成内容 CRC32 |
| 调色板前缀顺序 | 集合一致，顺序不同。OSD1 单色屏不读调色板 |
| 几个 `.h` 里的时间戳 | — |

顺带：固件里 `ui_style_file_version_compare` / `res_file_version_compare` /
`str_file_version_compare` 三个版本校验**都没人调**，这份固件树里也没有
`res_ver.h`，所以 `resver` 对不上不会有任何后果。
