# 做完界面怎么导出

完整的命令行选项表在工具自己的 `UIProject/tool/README.md`「命令行一览」，
这里只讲**流程、验收点和安全规则**。

---

## 1. 整条链

```
工程.uiproj
   │
   │  UITools.exe --gen            布局
   ├─► project.bin        窗口/控件布局（二进制）
   ├─► ename.h            控件/窗口 ID（哈希）
   ├─► Resbuilder.xml     打包用的配置（图片清单、颜色表、字体、excel_path）
   └─► debug.txt          可读的结构转储，排查用
   │
   │  UITools.exe --pack           资源（--gen --run-resbuilder 会自动接着跑）
   ├─► result.bin         图片资源
   ├─► result.str         字符串图片
   └─► result.h / res_ver.h / result_pic_index.h / result_str_index.h
       result.csv / result.xml
   │
   │  收尾脚本（默认 copy_file.bat，在工程目录里）
   └─► 拷进固件树
```

日常就一行，在工程目录里跑：

```
..\tool\UITools.exe --gen --run-resbuilder
```

不给工程文件时，它读当前目录 `config\ini\project.ini` 的 `projectfilename`。

编辑器界面上的「资源导出」走的是同一份代码，等价。

---

## 2. 收尾脚本把什么搬到哪

`copy_file.bat` 是**每个工程自己的**（就在工程目录下），可以改。
本仓库那份做的是：

| 产物 | 去处 | 说明 |
|---|---|---|
| `project.bin` | `tools/JL/JL.sty` | 布局 |
| `result.bin` | `tools/JL/JL.res` | 图片 |
| `result.str` | `tools/JL/JL.str` | 字符串图片 |
| `ename.h` | `User/ui_framework/include/common/style_jl02.h` | **ID 头，必须和资源一起换** |

⚠ ID 头和资源**必须同一次生成的配套**。`JL.sty` 里存的是那次生成出来的 ID，
只换资源不换头（或反过来），控件全找不到。

本仓库后面还有一步（这是 STM32 工程的做法，别的工程不一定有）：
`tools/make_res_image.py` 把 `tools/JL/` 打成 FAT12 磁盘镜像
`User/fs/res_image.c`，随固件烧进片内 Flash。它挂在 MDK 的 Before Build 上自动跑，
内容没变就不重写。

---

## 3. ⚠ 别在正在用的工程上随便跑

`--gen --run-resbuilder` 默认会执行收尾脚本，**直接覆盖固件树里的资源和 ID 头**。
试排版、验证 json 改得对不对的时候，这是不想要的。

三种做法，按场景选：

| 场景 | 做法 |
|---|---|
| 只想验证 json 改得对 | `--gen --no-script`，产物留在工程目录，不动固件树 |
| 想连资源一起验 | `--gen --run-resbuilder --no-script` |
| 想比对和现有产物是否一致 | `--gen --verify <现有产物目录>`，逐字节对比，有差异返回非零 |
| 真要更新固件 | 不加 `--no-script`，跑完检查 git diff |

还有一条容易忽略的：**编辑器保存工程时会把文件名写回 `config/ini/project.ini`**。
所以打开过别的 `.uiproj` 再跑生成，出来的可能是另一套界面的资源。
跑之前先确认 `projectfilename` 是不是你要的那个。

---

## 4. 验收点

每一步都有能自动判的检查，**不要靠肉眼看**：

> ⚠ **工具的输出是 GBK。** UTF-8 终端里直接看全是乱码，要
> `2>&1 | iconv -f GBK -t UTF-8`。退出码是准的，但警告内容看不懂等于没看。

| 阶段 | 命令 | 判据 |
|---|---|---|
| 改完 json | `--json-roundtrip <文件>` | 退出码 0（读进来写出去逐字节相同） |
| 同上，更严 | `--json-rebuild <文件>` | 退出码 0（每个节点标脏重建仍逐字节相同） |
| 语义体检 | `tools/check_project.py <文件>` | 退出码 0（roundtrip 放行的那些错） |
| 看排版对不对 | `--shot <png>` / `--preview-dump <目录>` | 出图，**读图确认** |
| 生成 | `--gen ...` 的输出 | 不能有「认不出控件类型」之类的警告 |
| 和既有产物比 | `--gen --verify <目录>` / `--pack --verify <目录>` | 退出码 0 |
| 结构对不对 | `--sty-dump <JL.sty>` | 打印控件树 + 往返校验 |

`--json-roundtrip` 只证明**格式**没写坏，不证明**语义**对
（caption 改错、ename 重复、rect 超出父节点，它都照样通过）。
所以排版必须靠出图看，类型必须靠 `--gen` 的警告看。

### 时间戳会让"逐字节比对"出假差异

`res_ver.h` / `result_pic_index.h` / `result_str_index.h` 里有
`Generated By ... <时间>` 行，`.sty` 头第 4 字节起是时间戳。
比对产物时这四处必然不同，**其余文件应当逐字节一致**。

## 5. 出图看效果

这是给 AI 用的关键一环 —— 不用开界面也能看见排版结果。**改完排版一定要出图看过
再说做完了。**

推荐这一条（实测过）：

```
UITools.exe --shot out.png --no-chrome --zoom 400 <工程文件>
```

要点，都是实测出来的：

- **抓的是整个编辑器主窗口**，不是只有画布那一小块。
  窗口约 1694×1032；本仓库的 128×64 工程在 `--zoom 400` 时画布位于
  **(511,66)–(1023,322)**（左上角固定，右下角 = 左上角 + 屏宽高 × 倍率／100，
  换个分辨率的工程自己算）。
  要只看排版就按这个框裁一下；不裁也能看，就是周围一圈 IDE 界面。
  不放大的话画布只有指甲盖大小 —— **`--zoom` 不是可选项**。
- **只画当前页**，也就是工程 json 根节点 `activePage` 指的那一页，
  **没有"截第几页"的参数**。多页工程要逐页出图只能改 `activePage` 另存临时工程：

  ```sh
  for i in $(seq 0 $((n-1))); do
      python -c "import json,io,sys
  d=json.load(io.open('$PROJ',encoding='utf-8')); d['activePage']=$i
  json.dump(d,io.open('_shot.uiproj','w',encoding='utf-8'),ensure_ascii=False,indent=4)"
      UITools.exe _shot.uiproj --shot p$i.png --no-chrome --zoom 400
  done
  ```

  临时工程只用来出图，不要拿它覆盖真工程（它没走规范化）。
- 窗口右侧的「页面」栏里有每一页的缩略图，想一眼扫全部页面时看那一栏也行。
- `--no-chrome` 关掉控件描边/选中框/控件名/像素网格，更接近真实显示效果。
- 走 `QWidget::grab()`，锁屏、无人值守都能出图。

另一个角度：

```
UITools.exe --preview-dump <目录> <工程文件>
```

把**每个控件**的内容各存一张 PNG，文件名形如 `005_Text_文字_12.png`
（序号_类型_节点名）。样本工程会出 300 张。适合查单个控件渲染得对不对
（文字有没有超框、图片选对了没），不适合看整体排版。

## 6. 改工具本身时的两个坑

只有在动 `tool_src` 时才用得上，做界面用不到。

### `dist.bat` 会静默失败

exe 被占用时（上一次 `--ops-test` / `--dialog-smoke` 的实例还没退、
或者编辑器开着），`copy` 拷不过去，但脚本**照样打印 done**。
结果是「改了代码、编译过了、跑出来还是旧行为」，能查很久。

**部署后核对时间戳**：

```sh
ls -la --time-style=+%H:%M:%S C:/bt/uitools-static/UITools.exe <工程>/tool/UITools.exe
```

两个对不上就是没拷成；`Get-Process UITools` 看谁占着。

### ops-test 的视觉断言不能依赖累积状态

`--ops-test` 有 400 多项，跑到后面模型已经被改得面目全非：
建过一堆控件（都带控件库的彩色背景色 = 擦灭）、删过节点、改过属性。

所以「画布上有 N 个亮点」这类断言**会随渲染语义的改动而失真** ——
不是渲染坏了，是那时候的工程本来就剩不下几个亮点。

写这类断言要选和内容无关的判据，例如：

- 「画布有内容时右栏也得有」（拿画布当基准，两边同一个模型）
- 「这张图光栅化得出点亮像素」（验能力，不验最终合成结果）

另外**加完节点要删掉**：ops-test 里「拖图层落到页上」加的那个图层如果不删，
它带的默认背景色会把整页擦灭，后面所有视觉断言全部失真。
